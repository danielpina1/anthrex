## Goal

After this milestone a developer or an agent runs `cargo nextest run --workspace` and `cargo test --workspace --doc`: a hung test is ended after ten minutes instead of holding CI open; tests that spawn PTYs, git or a daemon run at most eight at a time; the timing tests run alone; a failure is never retried away. Touching any file under `crates/daemon/src` rebuilds nothing of `anthrex-tui`. `daemon` and `cli` each link one integration-test binary plus a short, justified list of single-purpose ones. A test fails the moment an engine file imports `tokio`, the file system, processes, threads or the clock. CI audits dependencies and scans for secrets without blocking, and fails when a daemon, a `fake-agent` or an anthrex temporary directory outlives the suite. `rustc` is 1.99 everywhere. A test binary handed to the wrong checkout refuses to run.

## Design decisions

Numbered and final. If one proves wrong or impossible, stop work on it, record the evidence under "Implementation notes", and continue with the tasks that do not depend on it.

### nextest

1. **nextest runs the suite; doctests stay on libtest.** `cargo nextest run --workspace` replaces `cargo test --workspace` everywhere a command is documented or run (CI, `AGENTS.md`, `CONTRIBUTING.md`, `README.md`). Doctests run with `cargo test --workspace --doc`, which nextest cannot run. The workspace has no doctest today (no `rust` code fence in a doc comment, `56f87a1d`); the command still runs so a future one is not silently skipped. `cargo test --workspace` keeps working and is not removed from anyone's hands: the merged binaries must pass under it too (decision 13).
2. **Slow-timeout.** `slow-timeout = { period = "60s", terminate-after = 10 }`: a test is reported SLOW each minute and terminated at ten (nucleos lost 5.6 hours to one hung test; the research). The slowest test measured in M9.12.1 is recorded next to it; if it is above 300 s, stop and record (the bound would be within a factor of two of a real test).
3. **No retries, no fail-fast.** `retries = 0` (a retry hides the flake `docs/timing-budgets.md` wants found at its root; Stabilization's R6). `fail-fast = false`, matching CI's `--no-fail-fast` today and the user's rule to diagnose every failed test before pushing.
4. **Test threads.** `test-threads` stays nextest's default, the number of CPUs (libtest's default inside one binary today, so the machine never runs more tests at once than it did).
5. **The `real-io` group, width 8.** Tests that spawn a PTY, run real `git`, start a daemon (in-process `serve` or the `anthrex` binary) or exec a stand-in run in test group `real-io` with `max-threads = 8`. Membership is `kind(test)` (every integration-test binary in the workspace) plus the library-test modules that do the same, listed by module path in the filter (M9.12.3 builds the list with the `grep` in its Step 2 and records it). Width 8 because the budgets in `docs/timing-budgets.md` were measured under libtest, which runs one binary at a time with up to one test per CPU, and today's integration binaries hold on average 5 (`cli`, 449/91) to 8 (`daemon`, 676/83) tests: libtest has rarely run more than about eight such tests at once, and nextest must not either. Light tests fill the remaining threads.
6. **Timing tests run alone.** A *timing test* asserts an upper bound on elapsed wall-clock time as the property under test (`assert!(elapsed < …)` or an equivalent `Instant` comparison), as opposed to a deadline loop whose bound only ends a wait. Each one is named in the first override with `threads-required = "num-test-threads"` (it starts only when no other test runs, and nothing starts beside it) and `test-group = "timing"` (`max-threads = 1`). Known before M9.12.3's sweep: the four `< 100ms` lock-latency asserts (`daemon/tests/manager.rs`, `manager_worktree/admission.rs`), `an_exited_window_is_removed_without_waiting`, `without_a_daemon_it_exits_zero_silently_and_fast` (`cli/tests/hook_command.rs`) and `stderr_is_bounded_and_does_not_block_the_child` (`daemon/tests/subprocess.rs`). Each entry is written as `test(/(^|::)<name>$/)`, so it names the same test before and after the binary merge.
7. **Overrides are ordered timing first.** nextest takes each setting from the first override that matches and sets it, so the timing override comes first: a timing test is never also put in `real-io` by the second override.

### The engine-purity rule

16. **What it forbids.** Under `crates/daemon/src/run/engine/`, production code must not name: `tokio`; `std::fs`, `std::process`, `std::thread`, `std::env` (as a path or inside a grouped `use std::{…}`); `SystemTime`, `UNIX_EPOCH`, `Instant::now`; `libc`; `portable_pty`. NA §6 says "async runtime, file system, process, thread or clock APIs"; `std::env` (the process's environment), `libc` (raw system calls of every one of those kinds) and `portable_pty` (processes) are that list's other spellings. `Duration` and `std::path` are allowed (values, not I/O).
17. **What counts as production code.** Every `.rs` file under `run/engine/` except: `run/engine/tests/**`; each file mounted only under `#[cfg(test)]` (a `#[cfg(test)]` attribute line, optionally with `#[path = "…"]`, followed by `mod <name>;`; found by reading those declarations, so a new test file needs no list); and the brace-matched body of each inline `#[cfg(test)] mod <name> { … }`. Comment lines (`//`, `///`, `//!`) are skipped; `#[cfg(test)]` counts only as a line of its own (after trimming), never inside a string (`weakening.rs:151`). The rule checks direct uses only (Scope, "Out").

### CI gates

18. **The `security` job is non-blocking.** A separate job `security` on `ubuntu-latest` with `continue-on-error: true` and `timeout-minutes: 15`: checkout with `fetch-depth: 0` (gitleaks reads history), the toolchain from `rust-toolchain.toml`, `cargo audit` (pinned `cargo-audit`, decision 8), and `gitleaks` (pinned release binary, its SHA-256 checked against the release's checksums file) run with `--redact --no-banner` over the repository's history, so a found secret never reaches the log. A finding judged a false positive goes in `.gitleaksignore` with its reason in "Implementation notes"; a real one stops the task and is reported to the user, never committed around. Both tools need the network, which is why the job does not block (the research, item 6).
19. **The leak gate inspects; it never signals.** `scripts/leak_gate.py` has three modes. `snapshot <file>` writes the matching processes (pids) and temporary entries present now. `check <file>` waits until no new matching process remains or `PROCESS_WAIT` (30 s) passes, then fails (exit 1) when a matching process or temporary entry exists that the snapshot did not hold, printing each process's pid, ppid and command line and each entry's path. `selftest` proves both checks bite (Interfaces). It never calls `kill`, `os.kill`, `pkill` or `killall` on anything but the one child process `selftest` itself started, by that child's pid (hard rule 1; the user's standing rule). `PROCESS_WAIT` is derived: a test daemon's stop is `HANDSHAKE_TIMEOUT` (5 s) + `HUP_GRACE` (1 s) + `KILL_GRACE` (3 s) + `wait_released`'s cap (10 s) = 19 s (`docs/timing-budgets.md`, the `daemon stop` row), plus slack.
20. **What the leak gate matches.** A process whose argv[0] basename is `anthrex` and argv[1] is `daemon`, or whose argv[0] basename is `fake-agent`; zombies are not counted (no process to leak, and its parent is what would be). A temporary entry is a file or directory directly in `/tmp` or in the system temporary directory (`$TMPDIR` when set, else `/tmp`) whose name starts with `ax-` or `anthrex-`; for `anthrex-worktrees` (a shared root, not a test's directory) its children are compared instead. Files count as well as directories: a leftover `anthrex-reply-*.md` holds message text. Patterns are re-derived in M9.12.1 from the code ("Starting point", temporary names).
21. **Where the gate runs.** In the `ci` job on both systems: `selftest`, then `snapshot` before the suite, then `check` after the smoke with `if: always()`, so a red suite still reports what it left behind. A test that nextest's slow-timeout terminated leaves its daemon's PTY sessions in their own sessions alive; the gate is what reports them.
22. **The client's tree is checked in CI.** A step in the `ci` job fails when `cargo tree -p anthrex-tui -e all` names `anthrex-daemon` (decision 11).

## Risks and gotchas

- **Cross-binary collisions are new.** libtest ran one binary at a time; nextest overlaps tests from every binary. Any fixed path shared by two binaries (`/tmp/anthrex-mcp-cli-none.sock` in `cli/tests/mcp_cli.rs`, the shared `<temp>/anthrex-worktrees` root, a fixed port) can now collide. M9.12.4's stress runs are where this shows; fix the path to be per test.
- **Per-binary caches become per-test.** A `OnceLock` that built or wrote something once per binary (`fake-agent/tests/headless_support/mod.rs:49` may run a nested `cargo build` of `anthrex` when the sibling binary is missing; `orch_support/mod.rs:122`'s wrapper) now runs in every test process. `cargo nextest run --workspace` builds `anthrex` next to `fake-agent`, so the nested build is not reached; `-p anthrex-fake-agent` alone may reach it once per test.
- **macOS first-exec cost** is paid at nextest's listing (it runs each binary once with `--list`), not inside a test; stand-ins written by tests are still fresh per test (decision 9).
- **A test that nextest terminates** gets SIGTERM, then SIGKILL, for its process group; a PTY session it started is in its own session and survives. The leak gate reports it; never "fix" that by killing by name.
- **`#[path]` and `include_*!` paths** in moved files: path attributes on module declarations resolve against the declaring file's directory and move with it; `include_str!`/`include_bytes!` paths are relative to the file and need one more `../`.
- **Test names change** in the merge (`<file>::<test>`); anything that names a test (a filter, a re-exec, a doc or brief citing `--test <file>`) must change with it. Later briefs cite `cargo test -p anthrex --test <file>`; that becomes `cargo nextest run -p anthrex -E 'test(/^<file>::/)'`, and M9.12.12's `AGENTS.md` note says so.
- **`rustup` and the toolchain file**: an older rustup on a runner may not install from `rust-toolchain.toml` without an argument (decision 24's fallback). The release job's targets must be added after the pinned toolchain is active, or `cargo build --target` fails with a missing target.
- **The pinned 1.99 is today's stable** (released 2026-10-01); a later stable is not picked up until a deliberate bump commit (U16).
- **`check_branch_syntax`'s dedupe** removes one test and adds one; the count difference is expected and recorded, not a lost test.
