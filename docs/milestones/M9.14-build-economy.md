# Milestone 9.14: Build economy

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (the user's standing choice) to implement this brief task by task, TDD. Steps use checkbox (`- [ ]`) syntax for tracking.

Every `file:line` below was re-read there and is relative to `crates/` unless the path says otherwise; "Starting point" lists the anchors the design research had wrong. **Goal.** Many checkouts of one Rust workspace stop building everything cold and stop fighting over the CPU. A task worktree, its proof scratch, the integration checkout and the tier-3 checkout each build in a warm target directory leased from a small per-repository pool, cleaned of the previous owner's own packages so no stale binary is ever run. A headless Claude worker's own `cargo` commands wait for the daemon's test scheduler, below every engine step, for at most 300 s. A module's test step is skipped when nothing its module closure reads has changed since a green run.

**Architecture.** Three independent parts. **A, the target pool:** a pure book per repository (`run/target_pool/book.rs`) behind a daemon-wide service (`run/target_pool/mod.rs`) that the driver calls right before it executes an op; the service leases a directory for the op's checkout, substitutes it for `CARGO_TARGET_DIR` in the op's environment, and grants it to the worker sandbox and to the confined check. Releasing a checkout (its removal) cleans its path packages out of the directory. **B, admission:** a third `PreToolUse` hook group on headless Claude workers runs `anthrex admit`, which, outside the worker's Bash sandbox, asks the daemon's `TestScheduler` for slots in a new lowest class and blocks until it gets them or its wait runs out; the hold is released by the matching `PostToolUse` the status hook already forwards. **C, the per-module cache key:** a module test step's cache key names an inputs id over the files its module closure can read instead of the whole tree.

**Tech stack.** Rust 2024 workspace; `serde`/`rmp-serde` wire types; `sha2` (already a daemon dependency, `launch/codex.rs`); real `cargo` in a temporary workspace for the pool's clean tests; `fake-agent` for every agent.

**Spec.** NA §3 and §1.1 (U1, U6, U7, U8). Read them before task M9.14.2.

The user's decisions that bind every decision here (NA §1.1, quoted from the design gate of 2026-10-10):

- **U6** The target-directory pool is on by default when the stored profile's env sets `CARGO_TARGET_DIR` with `{worktree}`: `max_writers + 2` task dirs, 2 engine dirs, 20 GB cap per dir, idle dirs wiped after 7 days; a config table tunes or disables it.
- **U7** Build admission applies to headless workers only (an opt-in key for interactive windows, default off); the longest wait is 300 s, then the command runs anyway. The hook's timeout is the wait plus 30 s.
- **U8** Per-module test cache keys, with tier 3 as the backstop.

## Design decisions

Numbered and final. If one proves wrong or impossible, stop work on it, record the evidence under "Implementation notes", and continue with the tasks that do not depend on it. A decision marked **(R)** is a ruling on something NA §3 or the design research leaves open or says inconsistently; each is listed again under "Rulings on the design".

### A. The target pool

1. **On by default** (U6). The pool applies to an op when all of these hold: `[target_pool] enabled` (default `true`); the run's repository root is not in `[target_pool] disabled_repos`; `run.profile_source == Some(ProfileSource::Stored)`; and the stored profile's `env` has a `CARGO_TARGET_DIR` whose value contains `{worktree}` (the profile saying "this is cargo, one target per checkout"). There is no new profile key, so the 9.10 simple profile is unchanged. Otherwise every op keeps the profile's value, exactly as today.
2. **Sizes** (U6). Per repository: `task_dirs` (default `[orchestrator] max_writers + 2`, so 5 with the default 3), `engine_dirs` (default 2), `max_gb` (default 20) per directory, `idle_days` (default 7). The daemon reads `[target_pool]` and `max_writers` once at start, as it reads `test_slots`.
3. **Layout.** `<repo_dir>/target-pool/` where `repo_dir` is `profile::repo_dir(data, project)` (`run.repo_dir`): directories `task-<k>` (`k` from 1 to `task_dirs`) and `engine-<k>` (1 to `engine_dirs`), the lease table `leases.json` beside them, and `trash/` for wipes in progress. Every pool path is spelled as `confine::plain_dir` spells a checkout: the parent resolved, the leaf appended and checked with `lstat`; a pool directory that is a link or not a directory is wiped (renamed away) and recreated before it is leased.
4. **The owner is the checkout path**, not the task or the session (NA §3). A lease runs from the first op in a checkout to that checkout's removal, so every worker session, check, proof and tier step in it shares the directory. The task worktree and its proof scratch are different owners.
5. **Leases are exclusive, with affinity.** A checkout that already holds a directory gets it again. Otherwise it gets a free directory of its class whose last owner was this same path, if one exists; otherwise the free directory of its class used least recently (a never-used directory counts as oldest; ties go to the lowest `k`).
6. **Two classes that never cross.** `Engine`: the run's `integration_path()` and `full_path()`. `Task`: every other directory directly under `<wt_dir>/runs/<run id>/` (task worktrees, race lanes, `<task>.proof`) except a name ending `.review`. Anything else (a `.review` checkout, profile verification's `.profile-verify`, onboarding) gets no lease and keeps the profile's value. A directory is never moved between classes: a rejected task's poisoned artifact can then reach only task-level verdicts, never the integration checkout's.
7. **No free directory: fall back, never wait.** The op keeps the profile's value (today's cold `{worktree}/target`). The first time a checkout falls back, the run log gets `target pool: no free <class> directory for <checkout>; it builds in its own target directory` (`<class>` is `task` or `engine`, `<checkout>` the checkout's file name), once per checkout per daemon lifetime.
8. **Clean on release (R).** When a checkout is removed (`driver/cleanup.rs::remove_keeping`, before `git::remove_checkout`; a `keep_path` removal keeps its lease), its directory is cleaned while the outgoing checkout still exists:
   1. If the directory is over `max_gb` (measured on a blocking thread, `POOL_MEASURE_TIMEOUT`), wipe it instead and stop.
   2. `cargo metadata --format-version 1 --offline --locked` in the outgoing checkout (full, not `--no-deps`).
   3. The clean list is every package with `"source": null` (workspace members and vendored path crates), each as `<name>@<version>`.
   4. For each profile directory in the pool directory that has a `.fingerprint/` (`debug` → `--profile dev`, `release` → `--profile release`, any other name `<p>` → `--profile <p>`): one `cargo clean --offline --profile <p> -p <spec> -p <spec> …`.
   5. Wipe instead if any step fails or times out, if a `<target triple>/` directory exists in the pool directory, or if two packages in the clean list share a name and version.
   The commands run in the outgoing checkout with the environment `apply` last substituted for it (the pool keeps it in memory per leased checkout; after a restart, when it is unknown, the daemon's own environment), `CARGO_TARGET_DIR` the pool directory, through `confine::confined` with the run's `ConfineSpec` (the same rights as a check: the checkout belongs to code a worker wrote), under one `POOL_CLEAN_TIMEOUT` for the whole sequence, on `spawn_blocking`. No new kill code: `run_confined`'s existing timeout handling ends the commands. A directory cleaned this way is `Clean`; one whose owner vanished without a release (a crash, a checkout removed outside the daemon) is `Dirty` and is wiped before its next lease.
9. **Substitution in the driver, not in the op builders (R).** Ops are built by the pure engine and journaled before they run (M8a decision 43). Right before `driver/ops.rs::run` executes an op, `TargetPool::apply(&mut OpCtx, &mut OpKind)` leases a directory for each checkout the op names (decision 6), replaces the value of `CARGO_TARGET_DIR` in every `env` the op carries for that checkout (nested `TierSpec`s included), and records the grant (decisions 10, 11). The journal keeps the profile's value; a replayed op is applied again and gets the same directory (decision 5). No op builder changes, so they stay pure.
10. **Worker grants.** For `OpKind::CreateWindow`, `apply` adds the leased directory to `spec.claude_sandbox.writable_roots` (when `Some`) and, for a Codex session, to `spec.codex_writable_roots`. The spec is persisted with the window (`WindowRecord.run`), so a resumed or restored session keeps the same directory and grant.
11. **Confinement grant.** `ConfineSpec` gains `target_dir: Option<PathBuf>`, set by `apply` on the op's own `OpCtx` copy; `ConfineSpec::for_checkout` adds it to `writable` after `plain_dir` checks it. It is not routed through `cache_dirs` (`confine_cache::Areas` refuses anything under the data directory, correctly, for a user-written entry).
12. **Wipe.** Rename the directory to `trash/<class>-<k>-<unix secs>-<n>`, recreate it empty (mode 0700), and delete the trash on a blocking thread in the background. The lease waits only for the rename and the `mkdir`. Trash left by a crash is deleted at the next start.
13. **Idle sweep.** At daemon start and every `POOL_SWEEP_EVERY`: free directories whose `last_used` is older than `idle_days` are wiped (state `Fresh`), leases whose owner directory no longer exists are freed as `Dirty` (they keep `last_owner` for affinity), and each repository's `leases.json` is saved on a blocking thread.
14. **The table on disk.** `leases.json`, written atomically (temporary file, `fsync`, rename) after every change, outside the lock. Shape: `{"version":1,"dirs":[{"class":"task","k":1,"state":"leased","owner":"/abs/checkout","last_owner":"/abs/checkout","last_used":1760000000}]}`. `state` is `fresh`, `clean`, `leased` or `dirty`. An unreadable file means every directory is `Dirty`. A size change in config (fewer directories) wipes and deletes the directories past the new count when they are free; leased ones go when released.
15. **Disk bound.** At most `(task_dirs + engine_dirs) × max_gb` per repository, 140 GB with the defaults and `max_writers = 3`, between releases; the cap is enforced at release only.

### B. Admission for agents' own builds

16. **Block, never rewrite** (NA §3). A third `PreToolUse` group, matcher `Bash`, runs `anthrex admit`. The hook process runs outside the Bash sandbox (fact F1), asks the daemon for slots, blocks until a grant or the wait runs out, then exits 0 with no output (fail-open: every error, timeout and missing daemon also exits 0 silently). Bash then runs the command unchanged. The filter hook keeps its `updatedInput` rewrite; admission writes none, so two parallel hooks never race on the input (fact F2). The worker's Unix-socket pin (`argv.rs:84-96`) stays closed.
17. **Who gets the group.** Headless Claude sessions built by `worker_spec` (workers, race lanes and test writers) when the run's frozen `admit_wait_secs` is above 0. Never a Codex session, a reviewer, a planner, a scout, a design agent or the orchestrator. Interactive Claude windows only with `[testing] admit_interactive = true` (default `false`, U7).
18. **What counts as heavy.** A `Bash` call whose `tool_input.command`, after `output_filter::strip_leading` (leading `cd <dir> && ` segments and `NAME=value` assignments), starts with one of `HEAVY_COMMANDS` or one of the run's `filter_prefixes`, or contains a segment that does after `&&`, `||`, `;` or `|` (each segment stripped the same way). A prefix matches a whole word: `cargo test` matches `cargo test -q` and `cargo test`, never `cargo testing`. `HEAVY_COMMANDS = ["cargo build", "cargo test", "cargo check", "cargo clippy", "cargo nextest", "cargo bench", "cargo doc", "cargo run", "cargo-nextest"]`. Background calls (`run_in_background: true`) are admitted too; their hold is released at their `PostToolUse`, which comes when they start: early, and fail-open.
19. **The class.** `Priority::Agent`, appended after `Verify`, the lowest. The book's existing rule (only the first waiter may be granted) means a waiting agent ask never delays an engine ask: every engine class sorts ahead of it. A **granted** agent hold is like any running step: it is never pre-empted, so an engine ask waits for it to end (timing-budgets standing rule 5). The hold's length is bounded by its release events and by `admit_hold_max_secs`.
20. **How many slots.** A worker asks `Want::Count(n)` with `n` its M9.1 decision 27 cap, `max(1, test_slots / max_writers)`, the same number its `CARGO_BUILD_JOBS` already says. `Want::Count(n).of(slots)` is `n.clamp(1, slots)`. An interactive window (decision 17) asks `Want::Half` (R): its cargo is not capped, so it asks what a gate step asks.
21. **The wait.** The hook command carries `--wait-secs W` with `W = min(admit_wait_secs, stall_after_secs / 2)` from the run's frozen limits (R; 300 with the defaults `300` and `600`: a worker silent in a hook and then in its command must not reach the stall interrupt on the wait alone). The daemon waits at most `min(W, ADMIT_WAIT_MAX_SECS)` and then answers `AdmitTimedOut`. The client gives up at `W + ADMIT_CLIENT_GRACE` from its own start, whatever it is doing. The hook's settings `timeout` is `W + ADMIT_HOOK_SLACK_SECS` (U7). So daemon < client < Claude Code, each by a named margin.
22. **Release.** A hold is keyed `(window id, tool_use_id)`. It is released by that tool use's `PostToolUse` (and `PostToolUseFailure` if fact F4 finds the event), which the status hook already forwards (`hooks.rs:38,113`); every hold of a window is released by the window's `Stop`, `StopFailure`, `UserPromptSubmit` or `SessionEnd`; and the sweep (every `ADMIT_SWEEP`) releases holds older than `admit_hold_max_secs` and holds of windows the manager no longer lists. A call without a `tool_use_id` is not admitted (the client exits 0 at once without connecting): it could never be released by id.
23. **One ask per tool use.** A second `Admit` for a held `(window, tool_use_id)` answers `Admitted` with the held slots and takes nothing new. A client that disconnects while waiting abandons its ask (the waiting `acquire` future is dropped, which gives up its place). A grant whose `Admitted` frame cannot be written is dropped at once.
24. **Config.** `[testing] admit_wait_secs` (default 300, range `0..=ADMIT_WAIT_MAX_SECS`; 0 turns admission off), `admit_hold_max_secs` (default 1800, range 60..=86 400), `admit_interactive` (default `false`). `admit_wait_secs` is frozen into each run (`TestingLimits`); the other two are daemon-wide, read once at start. `ADMIT_WAIT_MAX_SECS` is 1800 unless fact F3 finds a smaller hook `timeout` limit `M`, in which case it is `M − ADMIT_HOOK_SLACK_SECS`, recorded with the evidence.
25. **Codex is not admitted** (NA §3): its sandbox has no network, so its commands cannot ask, and no blocking-hook fact is recorded. It keeps the M9.1 decision 27 caps. Fact F6 is recorded for a later milestone and changes nothing here.

### C. The per-module cache key

26. **The inputs id.** Only Scope::Gate steps that a module command made (a `module_tests` or `module_test` step, and the timing step of either) get it; such a step's `Step.per_module` is `true`. Its key's `tree` is `m1:<hex sha-256>` over the tree's entries (`git ls-tree -r -z --full-tree <tree>`), in git's order, each as `<mode> <object>\t<path>\0`, keeping a path when:
    - it is in no module (`globs::path_module` is `None`: root files, `.cargo/`, `Cargo.lock`, `rust-toolchain*`, `scripts/`, top-level fixtures, and the root package `.`'s own files), or its module's name cannot be found (`affected::module_name` fails); or
    - its module is in the step's closure: the modules of the step's `Affected::Modules` set plus, transitively, every module they depend on in the module graph (dependencies of every kind, dev-dependencies included, as `tiers/graph.rs:17` records them).
    When the closure holds every module of the graph, the key keeps the tree id (an inputs id over everything is the tree).
27. **Keys that do not change.** The build step (`-`), `full:` sets, Scope::Full (tier 3), a `check` step standing in for module tests, and every step of an untiered profile keep the tree id. Tier 3 stays the backstop for undeclared cross-module reads (U8).
28. **Why this is safe enough.** It trusts exactly what M9.1's affected rule already trusts: a change only inside module X's directory tests only X and its reverse dependencies. Known residual: `include_str!("../../other/…")` or a test reading another module's files at run time. Such modules belong in the profile's `hub` or `full_triggers`.
29. **Environment in the toolchain part.** `with_path` becomes `with_env(toolchain, step env)`: the key's toolchain part is `<toolchain> path:<fnv>` as today, followed by ` env:<fnv>` over `NAME=value\n` for each of `TOOLCHAIN_ENV_VARS = ["RUSTFLAGS", "RUSTDOCFLAGS", "RUSTC_WRAPPER", "CARGO_ENCODED_RUSTFLAGS", "CARGO_BUILD_TARGET"]` that is set (the step env's last value, else the daemon's own), in that order. With none set, the part is exactly today's, so existing cache lines stay valid. `CARGO_TARGET_DIR` and the four `SLOT_VARS` are never in a key: a leased directory or a slot count is not an input.
30. **Two amendments to ruling C-13 (R).** (1) Store a result only when the checkout is clean and at the **job's** tree (`outcome.tree`), not at `key.tree`: an inputs id is not a tree, so comparing against it would never store. (2) `usable_hits`: a later step's miss still forces the build step to run, but a build step's miss no longer voids later hits. A later step that hits needs no build; without this, a moved tree (which always misses the build step's key) would void every module hit and the inputs id would never pay off. With tree-id keys only, the amended rule gives the same answers as today (a build miss means the tree moved, so every later tree key misses too).
31. **The ls-tree read** runs once per tier job, only when at least one step is `per_module` and the job has a cache context, through `job.read` (the `GitQueue`, `--no-optional-locks`, the scrubbed environment; AGENTS.md rules 10 and 11). An error makes those steps keyless (a miss), never a wrong key. The tier-2 skip (`tier_cached.rs`) stays all or nothing and still misses whenever the build step does.

### Rulings on the design

The design research behind NA §3 (`m9.14.md` in the design gate) says, and this brief rules:

- **(R1) Decision 8, clean on release instead of "on owner change, in the new checkout".** The design runs `cargo metadata` in the new checkout before handing the lease over. For the ops that create a checkout (`PrepareWorktree`, `CreateRunBranch`, a proof's scratch, `TestAt`'s materialise) the new checkout does not exist yet when the lease must be decided, and their `setup` runs `cargo` right after creating it. Cleaning at release, in the outgoing checkout, always has a checkout to read, and still hands every new owner a directory free of the previous owner's path packages. Residual: a crate the outgoing checkout dropped from its workspace keeps its artifacts (risks).
- **(R2) Decision 9, substitution in the driver instead of "the leased path stored on the Run/Task model".** The pool is daemon-wide and shared by concurrent runs on one repository, so the engine cannot decide a lease purely; storing it on the model would need an extra op and result before every checkout's first op. Substituting in the driver keeps every builder pure, as the design wanted.
- **(R3) Decision 20, `Want::Half` for an interactive window**, which has no M9.1 cap to copy.
- **(R4) Decision 21, the wait is capped at `stall_after_secs / 2`.** The design did not relate the 300 s wait to the 600 s stall interrupt (`run/engine/clock.rs:112`).
- **(R5) Decision 26, `Step.per_module`.** The design's "steps whose affected key names modules" also matches the `check` step that stands in for module tests (`steps.rs:155`), which runs the whole suite and must keep the tree id (its decision 19).
- **(R6) Decision 30, both C-13 amendments.** The design keeps C-13 as is; as implemented, C-13 (1) would never store an inputs-id result and C-13 (2) would void every module hit whenever the tree moved, so the per-module key would never skip anything.
- **(R7) Decision 19 wording.** The design says agent asks "never delay engine work"; a granted hold does, until released (standing rule 5). The decision says what is true.

## Risks and gotchas

- **Shared target dirs and compile-time paths** (from milestone 9.12's brief). `env!("CARGO_BIN_EXE_*")` and `env!("CARGO_TARGET_TMPDIR")` bake a build directory into a test binary, as `CARGO_MANIFEST_DIR` does (which 9.12 guards). Under the pool a binary built by one checkout can name another checkout's paths. Task M9.14.1 audits every use and either guards it like 9.12's `CARGO_MANIFEST_DIR` guard or records why it is safe.

- **The task pool is smaller than two directories per writer.** A task worktree and its proof scratch are different owners (decision 4), so `max_writers` busy tasks want `2 × max_writers` task directories against `max_writers + 2` (U6). With the default 3 writers, a third task's proof scratch falls back to its own cold target (decision 7, one run log line). That is U6 as approved; record how often it happens in the end-to-end runs.
- **Disk.** Up to 140 GB per repository with the defaults (decision 15), enforced at release. A machine short of disk should lower `max_gb` or `task_dirs`, or set `enabled = false`.
- **A crate the outgoing checkout removed from its workspace keeps its artifacts** (ruling R1): its fingerprint is not in the clean list. A later owner that adds a crate of the same name and version with older sources could reuse them. Narrow; the integration checkout's engine directory never sees task artifacts (decision 6), so it cannot forge an engine verdict.
- **`cargo metadata --offline` fails without a warm registry**, which makes the clean a wipe: correct, only slower. A repository whose dependencies were never fetched on this machine wipes on every release until they are.
- **A pool directory is a write channel between tasks** in the task class. A worker can plant artifacts a later task's proof would use. Decision 6 confines the damage to task-level verdicts; the engine verdicts (integration, tier 3) stay clean.
- **An agent hold leaks when a `PostToolUse` is lost** (the status hook is best-effort with a 1 s deadline). The window's `Stop`, the sweep and `admit_hold_max_secs` bound it; a leaked hold delays engine steps by at most that long.
- **Fail-open over-subscribes.** After W the command runs unscheduled, beside the engine's steps. U7 chose this over unbounded waits.
- **The hook's wait is silence.** A worker waiting in the hook emits no stream event; decision 21 keeps the wait at most half of `stall_after_secs`, but a long build after a long wait can still reach the stall interrupt that would have fired anyway for a build that long.
- **`fake-agent`'s `bash` step changed.** Behind `FAKE_AGENT_TOOL_IDS` only; if a test outside this milestone's files changes, the variable leaked.
- **`OpKind` grows a new env-carrying variant later**: `apply`'s exhaustive match makes the compiler name it; the comment there says to classify it.
