# Milestone 9.14: Build economy

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (the user's standing choice) to implement this brief task by task, TDD. Steps use checkbox (`- [ ]`) syntax for tracking.

This milestone is built **after milestone 9.13 (hardening, protocol 22) merges**. Task M9.14.1 re-checks every name and line below on the merged `main` first and records what moved.

**Goal.** Many checkouts of one Rust workspace stop building everything cold and stop fighting over the CPU. A task worktree, its proof scratch, the integration checkout and the tier-3 checkout each build in a warm target directory leased from a small per-repository pool, cleaned of the previous owner's own packages so no stale binary is ever run. A headless Claude worker's own `cargo` commands wait for the daemon's test scheduler, below every engine step, for at most 300 s. A module's test step is skipped when nothing its module closure reads has changed since a green run.

**Architecture.** Three independent parts. **A, the target pool:** a pure book per repository (`run/target_pool/book.rs`) behind a daemon-wide service (`run/target_pool/mod.rs`) that the driver calls right before it executes an op; the service leases a directory for the op's checkout, substitutes it for `CARGO_TARGET_DIR` in the op's environment, and grants it to the worker sandbox and to the confined check. Releasing a checkout (its removal) cleans its path packages out of the directory. **B, admission:** a third `PreToolUse` hook group on headless Claude workers runs `anthrex admit`, which, outside the worker's Bash sandbox, asks the daemon's `TestScheduler` for slots in a new lowest class and blocks until it gets them or its wait runs out; the hold is released by the matching `PostToolUse` the status hook already forwards. **C, the per-module cache key:** a module test step's cache key names an inputs id over the files its module closure can read instead of the whole tree.

**Tech stack.** Rust 2024 workspace; `serde`/`rmp-serde` wire types; `sha2` (already a daemon dependency, `launch/codex.rs`); real `cargo` in a temporary workspace for the pool's clean tests; `fake-agent` for every agent.

**Spec.** NA §3 and §1.1 (U1, U6, U7, U8). Read them before task M9.14.2.

The user's decisions that bind every decision here (NA §1.1, quoted from the design gate of 2026-10-10):

- **U6** The target-directory pool is on by default when the stored profile's env sets `CARGO_TARGET_DIR` with `{worktree}`: `max_writers + 2` task dirs, 2 engine dirs, 20 GB cap per dir, idle dirs wiped after 7 days; a config table tunes or disables it.
- **U7** Build admission applies to headless workers only (an opt-in key for interactive windows, default off); the longest wait is 300 s, then the command runs anyway. The hook's timeout is the wait plus 30 s.
- **U8** Per-module test cache keys, with tier 3 as the backstop.

**Integration-test paths.** Since milestone 9.12 the daemon's and the CLI's integration tests are one binary per crate (`autotests = false`). This brief writes their paths as `daemon/tests/it/<f>.rs` and `cli/tests/it/<f>.rs`; a new one needs a `mod <f>;` line in `tests/it/main.rs`; only a file that mutates the process environment gets its own `[[test]]` entry. `source_rules::every_integration_test_file_is_compiled` fails on a file no target compiles.

## Design decisions

Numbered and final. If one proves wrong or impossible, stop work on it, record the evidence under "Implementation notes", and continue with the tasks that do not depend on it. A decision marked **(R)** is a ruling on something NA §3 or the design research leaves open or says inconsistently; each is listed again under "Rulings on the design".

### A. The target pool

1. **On by default** (U6). The pool applies to an op when all of these hold: `[target_pool] enabled` (default `true`); the run's repository root is not in `[target_pool] disabled_repos`; `run.profile_source == Some(ProfileSource::Stored)`; and the stored profile's `env` has a `CARGO_TARGET_DIR` whose value contains `{worktree}` (the profile saying "this is cargo, one target per checkout"). There is no new profile key, so the 9.10 simple profile is unchanged. Otherwise every op keeps the profile's value, exactly as today. **(R)** Such a profile must reach build outputs only through `$CARGO_TARGET_DIR`: a gate command or script that reads a literal `./target/…` worked while the two were equal and reads nothing (or a stale fallback `target/`) under the pool (C32; risks).
2. **Sizes** (U6). Per repository: `task_dirs` (default `[orchestrator] max_writers + 2`, so 5 with the default 3, **(R)** clamped to `TARGET_POOL_TASK_DIRS_RANGE`, C26), `engine_dirs` (default 2), `max_gb` (default 20) per directory, `idle_days` (default 7). The daemon reads `[target_pool]` and `max_writers` once at start, as it reads `test_slots`; a later live change of `max_writers` does not resize the pool.
3. **Layout.** `<repo_dir>/target-pool/` where `repo_dir` is `profile::repo_dir(data, project)` (`run.repo_dir`): directories `task-<k>` (`k` from 1 to `task_dirs`) and `engine-<k>` (1 to `engine_dirs`), the lease table `leases.json` beside them, and `trash/` for wipes in progress. Every pool path is spelled as `confine::plain_dir` spells a checkout: the parent resolved, the leaf appended and checked with `lstat`; a pool directory that is a link or not a directory is wiped (renamed away) and recreated before it is leased.
4. **The owner is the checkout path**, not the task or the session (NA §3). A lease runs from the first op in a checkout to that checkout's removal, so every worker session, check, proof and tier step in it shares the directory. The task worktree and its proof scratch are different owners.
5. **Leases are exclusive, with affinity.** A checkout that already holds a directory gets it again. Otherwise it gets a free directory of its class whose last owner was this same path, if one exists; otherwise the free directory of its class used least recently (a never-used directory counts as oldest; ties go to the lowest `k`). **(R)** A lease is decided under the book lock, then the chosen directory's `tokio::sync::Mutex` is taken (so a lease waits for a wipe or clean of that directory in progress), the `wipe_first` wipe is done under it, and it is released before the lease returns (C9). The lease is durable before it is used: the pool awaits the atomic save of `leases.json` (on `spawn_blocking`) before it hands the directory out; if the save fails it rolls the lease back in memory and the op falls back as in decision 7 (C10). A repository's table is loaded lazily on its first touch (on a blocking thread), so no lease depends on `restore` having run first (C10).
6. **Two classes that never cross.** `Engine`: the run's `integration_path()` and `full_path()`. `Task`: every other directory directly under `<wt_dir>/runs/<run id>/` (task worktrees, race lanes, `<task>.proof`) except a name ending `.review`. Anything else (a `.review` checkout, profile verification's `.profile-verify`, onboarding) gets no lease and keeps the profile's value. A directory is never moved between classes: a rejected task's poisoned artifact can then reach only task-level verdicts, never the integration checkout's.
7. **No free directory: fall back, never wait.** The op keeps the profile's value (today's cold `{worktree}/target`). The first time a checkout falls back, the run log gets `target pool: no free <class> directory for <checkout>; it builds in its own target directory` (`<class>` is `task` or `engine`, `<checkout>` the checkout's file name), once per checkout per daemon lifetime. **(R)** A checkout that fell back stays on the profile's value until it is released (its removal), even when a directory frees up meanwhile, so its builds never split between a cold pool directory and its warm `{worktree}/target` (C24).
8. **Clean on release (R).** When a checkout is removed (`driver/cleanup.rs::remove_keeping`; a `keep_path` removal keeps its lease), its directory is cleaned while the outgoing checkout still exists. **(R)** The release is its own `await` in `remove_keeping`, after the salvage and before `service.write(…git::remove_checkout…)`, never inside a `GitQueue` closure: a clean of up to `POOL_CLEAN_TIMEOUT` inside the project's write turn would stall every git write of every run on that repository (hard rules 2 and 10, C6). A checkout already gone (`path.exists()` false) is released not-cleaned (`Dirty`), with no `cargo`. A checkout kept by the nested-repository early return keeps its lease; the sweep's `reconcile` frees it once the user deletes the checkout (C6). **(R)** A **discarded** run's checkouts are all released not-cleaned (`Dirty`, wiped before their next lease) with no `cargo`: `cleanup::discard` passes `clean: false` to `remove_keeping` (C11). Every other removal cleans:
   1. If the directory is over `max_gb` (measured on a blocking thread, `POOL_MEASURE_TIMEOUT`), wipe it instead and stop.
   2. `cargo metadata --format-version 1 --offline --locked` in the outgoing checkout (full, not `--no-deps`).
   3. The clean list is every package with `"source": null` (workspace members and vendored path crates), each as `<name>@<version>`.
   4. For each profile directory in the pool directory (**(R)**, C21: a top-level directory that holds a `.fingerprint/`; `debug` → `--profile dev`, `release` → `--profile release`, any other name `<p>` → `--profile <p>`, a custom profile): one `cargo clean --offline --profile <p> -p <spec> -p <spec> …`. Cargo writes the `test` profile into `debug/` and `bench` into `release/`, so those names never appear as directories of their own. A profile directory whose profile the outgoing workspace does not define makes `cargo clean --profile` fail, which is a wipe: correct.
   5. Wipe instead if any step fails or times out, if a target-triple directory exists in the pool directory (**(R)**, C21: a top-level directory without `.fingerprint/` that holds `debug/` or `release/`), or if two packages in the clean list share a name and version.
   The commands run in the outgoing checkout with the environment `apply` last substituted for it (the pool keeps it in memory per leased checkout; after a restart, when it is unknown, the daemon's own environment), `CARGO_TARGET_DIR` the pool directory, **(R)** and, overriding whatever config the checkout holds, `RUSTC_WRAPPER=`, `RUSTC_WORKSPACE_WRAPPER=` and `CARGO_BUILD_RUSTC_WRAPPER=` (empty) plus `RUSTUP_TOOLCHAIN` when the profile's or the daemon's environment names one (`CLEAN_ENV_OVERRIDES`; a rejected checkout may still hold a bounced `.cargo/config.toml` or `rust-toolchain*`, C12). They run through `confine::confined` with the run's `ConfineSpec` (the same rights as a check: the checkout belongs to code a worker wrote) on the release's own copy of it, **(R)** whose `target_dir` is set to the pool directory (decision 11; without it `(deny default)` refuses the clean's writes and every confined release would wipe, C5), under one `POOL_CLEAN_TIMEOUT` for the whole sequence, on `spawn_blocking`. No new kill code: `run_confined`'s existing timeout handling ends the commands. **(R)** A directory cleaned this way is `Clean`; any wipe (here, at the idle sweep, or before a lease) leaves it `Fresh` (C20); one released not-cleaned, or whose owner vanished without a release (a crash, a checkout removed outside the daemon), is `Dirty` and is wiped before its next lease.
9. **Substitution in the driver, not in the op builders (R).** Ops are built by the pure engine and journaled before they run (M8a decision 43). Right before `driver/ops.rs::run` executes an op, `TargetPool::apply(&mut OpCtx, &mut OpKind)` leases a directory for each checkout the op names (decision 6), replaces the value of `CARGO_TARGET_DIR` in every `env` the op carries for that checkout (nested `TierSpec`s included), and records the grant (decisions 10, 11). The journal keeps the profile's value; a replayed op is applied again and gets the same directory (decision 5). No op builder changes, so they stay pure.
10. **Worker grants (R).** For `OpKind::CreateWindow`, `apply` adds the leased directory to `spec.claude_sandbox.writable_roots` (when `Some`) and, for a Codex session, to `spec.codex_writable_roots`, and records it as `OpCtx.pool_grant` on the op's own context copy. `driver/ops.rs::worker_git_dirs`, which runs after `apply` and **assigns** `grant.writable` to both lists for a sandboxed worker, appends `ctx.pool_grant` to `grant.writable` before assigning, for Claude and for Codex, so the grant survives (C1). The spec is persisted with the window (`WindowRecord.run`), so a resumed or restored session keeps the same directory and grant.
11. **Confinement grant.** `ConfineSpec` gains `target_dir: Option<PathBuf>`, set by `apply` on the op's own `OpCtx` copy (and by a release on its own copy, decision 8); `ConfineSpec::for_checkout` adds it to `writable` after `plain_dir` checks it. It is not routed through `cache_dirs` (`confine_cache::Areas` refuses anything under the data directory, correctly, for a user-written entry).
12. **Wipe.** Rename the directory to `trash/<class>-<k>-<unix secs>-<n>`, recreate it empty (mode 0700), and delete the trash on a blocking thread in the background. The lease waits only for the rename and the `mkdir`. Trash left by a crash is deleted at the next start.
13. **Idle sweep (R).** At daemon start (`restore`) and every `POOL_SWEEP_EVERY`: free directories whose `last_used` is older than `idle_days` are wiped (state `Fresh`), leases whose owner directory no longer exists are freed as `Dirty` (they keep `last_owner` for affinity), and each repository's `leases.json` is saved on a blocking thread. Races (C9): the sweep takes an idle directory's `tokio::sync::Mutex`, re-checks under the book lock that it is still free and idle, and marks it non-free (`PoolBook::begin_wipe`) for the wipe, so a concurrent lease cannot pick it up mid-rename. A lease is made before its checkout exists (R1), so the periodic sweep's `reconcile` frees an absent owner only when it was leased before the previous sweep; `restore` frees only absent owners leased before this daemon started, never a lease this daemon made (C9, reconciled with C10's lazy load). After the run service has loaded its runs, `restore` also frees, as `Dirty`, every lease whose run the daemon does not know (a checkout kept on purpose after its run is gone, C25).
14. **The table on disk.** `leases.json`, written atomically (temporary file, `fsync`, rename) after every change, outside the lock; **(R)** a lease's save completes before the lease is used (decision 5, C10). Shape: `{"version":1,"dirs":[{"class":"task","k":1,"state":"leased","owner":"/abs/checkout","run":"<run id>","leased_at":1760000000,"last_owner":"/abs/checkout","last_used":1760000000}]}` (`run` and `leased_at` only on a leased directory; C9, C25). `state` is `fresh`, `clean`, `leased` or `dirty`; a directory being wiped is saved as `dirty`. An unreadable file means every directory is `Dirty`. A size change in config (fewer directories) wipes and deletes the directories past the new count when they are free; leased ones go when released.
15. **Disk bound.** At most `(task_dirs + engine_dirs) × max_gb` per repository, 140 GB with the defaults and `max_writers = 3`, between releases; the cap is enforced at release only.

### B. Admission for agents' own builds

16. **Block, never rewrite** (NA §3). A third `PreToolUse` group, matcher `Bash`, runs `anthrex admit`. The hook process runs outside the Bash sandbox (fact F1), asks the daemon for slots, blocks until a grant or the wait runs out, then exits 0 with no output (fail-open: every error, timeout and missing daemon also exits 0 silently). Bash then runs the command unchanged. The filter hook keeps its `updatedInput` rewrite; admission writes none, so two parallel hooks never race on the input (fact F2). The worker's Unix-socket pin (`argv.rs:85-97`) stays closed.
17. **Who gets the group.** Headless Claude sessions built by `worker_spec` (workers, race lanes and test writers) when the run's frozen `admit_wait_secs` is above 0. Never a Codex session, a reviewer, a planner, a scout, a design agent or the orchestrator. Interactive Claude windows only with `[testing] admit_interactive = true` (default `false`, U7). **(R)** `launch::plan` builds the same Claude settings for user windows and for the orchestrator, so it adds the group only when `ctx.role.is_none() && admit_interactive && admit_wait_secs > 0` (a daemon-wide wait of 0 adds none, C22); the two values reach it through `ManagerConfig` → `LaunchContext`, which carry no `[testing]` value today (C7).
18. **What counts as heavy (R).** A `Bash` call whose `tool_input.command` has a heavy segment (C13). The command is tokenized as shell words (quotes kept together) and split into segments on unquoted `&&`, `||`, `;`, `|`, `&` and newline. Each segment is stripped of leading `cd <dir> &&` and `NAME=value` words (as `output_filter::strip_leading` does), then of the wrapper words `COMMAND_WRAPPERS = ["time", "nice", "env", "command", "nohup", "exec"]` (and `NAME=value` words after `env`). A segment is heavy when what remains:
    - starts with `cargo` (or a path ending `/cargo`) and, after skipping a `+<toolchain>` word and cargo's global flags (with the value of each of `CARGO_FLAGS_WITH_VALUE = ["-Z", "--config", "--color", "-C", "--manifest-path"]`, unless written `--flag=value`), its subcommand is one of `HEAVY_CARGO_SUBCOMMANDS = ["build", "b", "test", "t", "check", "c", "clippy", "nextest", "bench", "doc", "d", "run", "r"]`; or
    - starts with `cargo-nextest`, or with one of the run's `filter_prefixes` as whole words (`./slow-test` matches `./slow-test --all`, never `./slow-testing`).
    The matcher is advisory and fails open, not a boundary: `bash -c "…"`, `( … )` subshells and scripts can still evade it, and nothing stops that (record). Background calls (`run_in_background: true`) are admitted too; their hold is released at their `PostToolUse`, which comes when they start: early, and fail-open.
19. **The class.** `Priority::Agent`, appended after `Verify`, the lowest. The book's existing rule (only the first waiter may be granted) means a waiting agent ask never delays an engine ask: every engine class sorts ahead of it. A **granted** agent hold is like any running step: it is never pre-empted, so an engine ask waits for it to end (timing-budgets standing rule 5). The hold's length is bounded by its release events and by `admit_hold_max_secs`.
20. **How many slots.** A worker asks `Want::Count(n)` with `n` its M9.1 decision 27 cap, `max(1, test_slots / max_writers)`, the same number its `CARGO_BUILD_JOBS` already says. `Want::Count(n).of(slots)` is `n.clamp(1, slots)`. An interactive window (decision 17) asks `Want::Half` (R): its cargo is not capped, so it asks what a gate step asks.
21. **The wait.** The hook command carries `--wait-secs W` with `W = min(admit_wait_secs, stall_after_secs / 2)` from the run's frozen limits (R; 300 with the defaults `300` and `600`: a worker silent in a hook and then in its command must not reach the stall interrupt on the wait alone). The daemon waits at most `min(W, ADMIT_WAIT_MAX_SECS)` and then answers `AdmitTimedOut`. The client gives up at `W + ADMIT_CLIENT_GRACE` from its own start, whatever it is doing. The hook's settings `timeout` is `W + ADMIT_HOOK_SLACK_SECS` (U7). So daemon < client < Claude Code, each by a named margin.
22. **Release (R).** A hold is keyed `(window id, tool_use_id)`. It is released by that tool use's `PostToolUse` and by its `PostToolUseFailure` (fact F4: a failed `Bash` fires only the latter), which the status hook already forwards (`hooks.rs:38,113`); **(R)** a window's `PreToolUse` for a different `tool_use_id` releases that window's older holds (`Release::AllBut(id)`: a call admitted and then denied, refused by the sandbox, blocked by another hook or interrupted gets no `Post*` event, C8 (c)); every hold of a window is released by the window's `Stop`, `StopFailure`, `UserPromptSubmit` or `SessionEnd`; and the sweep (every `ADMIT_SWEEP`) releases holds older than `admit_hold_max_secs` and holds of windows that are not live, **(R)** where live means listed by the manager **and** not `Status::Exited` (a listed headless window whose process died, C8 (b)). A call without a `tool_use_id` is not admitted (the client exits 0 at once without connecting): it could never be released by id. Parallel `Bash` calls of one window can therefore release each other's holds early: fail-open, never a deadlock.
23. **One ask per tool use (R).** A second `Admit` for a held `(window, tool_use_id)` answers `Admitted` with the held slots and takes nothing new; **(R)** after a grant, the handler re-checks under the hold-book lock, and if the key is held by then (two asks for one key that both waited) it drops the new grant and answers `Admitted` with the held slots (C16). A client that disconnects while waiting abandons its ask: each connection has a `CancellationToken` cancelled as its read loop exits, and the detached admit task selects on it, which drops the waiting `acquire` future and gives up its place (C2). **(R)** On a grant the hold is inserted **before** `Admitted` is sent (C15); if the send fails or the connection's token is already cancelled, the hold is removed and its grant dropped. "Cannot be written" means "the connection closed before the grant was handed over": `mpsc::send` succeeds once the frame is queued, so a later write failure is not seen, and such a hold ends at its `Post*` event, the window's events or the sweep (C2).
24. **Config (R).** `[testing] admit_wait_secs` (default 300, range `0..=ADMIT_WAIT_MAX_SECS`; 0 turns admission off), `admit_hold_max_secs` (**(R)** default 630, `ADMIT_HOLD_MAX_DEFAULT_SECS`: the `Bash` tool's longest foreground `timeout`, 600 s on Claude Code, plus `ADMIT_HOOK_SLACK_SECS`, C8 (a); range 60..=86 400), `admit_interactive` (default `false`). `admit_wait_secs` is frozen into each run (`TestingLimits`); the other two are daemon-wide, read once at start. `ADMIT_WAIT_MAX_SECS` is 1800 unless fact F3 finds a smaller hook `timeout` limit `M`, in which case it is `M − ADMIT_HOOK_SLACK_SECS`, recorded with the evidence.
25. **Codex is not admitted** (NA §3): its sandbox has no network, so its commands cannot ask, and no blocking-hook fact is recorded. It keeps the M9.1 decision 27 caps. Fact F6 is recorded for a later milestone and changes nothing here.

### C. The per-module cache key

26. **The inputs id.** Only Scope::Gate steps that a module command made (a `module_tests` or `module_test` step, and the timing step of either) get it; such a step's `Step.per_module` is `true`. Its key's `tree` is `m1:<hex sha-256>` over the tree's entries (`git ls-tree -r -z --full-tree <tree>`), in git's order, each as `<mode> <object>\t<path>\0`, keeping a path when:
    - it is in no module (`globs::path_module` is `None`: root files, `.cargo/`, `Cargo.lock`, `rust-toolchain*`, `scripts/`, top-level fixtures, and the root package `.`'s own files), or its module's name cannot be found (`affected::module_name` fails); or
    - its module is in the step's closure: the modules of the step's `Affected::Modules` set plus, transitively, every module they depend on in the module graph (dependencies of every kind, dev-dependencies included, as `tiers/graph.rs:17` records them).
    When the closure holds every module of the graph, the key keeps the tree id (an inputs id over everything is the tree).
27. **Keys that do not change.** The build step (`-`), `full:` sets, Scope::Full (tier 3), a `check` step standing in for module tests, and every step of an untiered profile keep the tree id. Tier 3 stays the backstop for undeclared cross-module reads (U8).
28. **Why this is safe enough.** It trusts exactly what M9.1's affected rule already trusts: a change only inside module X's directory tests only X and its reverse dependencies. Known residual: `include_str!("../../other/…")` or a test reading another module's files at run time. Such modules belong in the profile's `hub` or `full_triggers`.
29. **Environment in the toolchain part.** `with_path` becomes `with_env(toolchain, step env)`: the key's toolchain part is `<toolchain> path:<fnv>` as today, followed by ` env:<fnv>` over `NAME=value\n` for each of `TOOLCHAIN_ENV_VARS = ["RUSTFLAGS", "RUSTDOCFLAGS", "RUSTC_WRAPPER", "CARGO_ENCODED_RUSTFLAGS", "CARGO_BUILD_TARGET"]` that is set (the step env's last value, else the daemon's own), in that order. With none set, the part is exactly today's, so existing cache lines stay valid. `CARGO_TARGET_DIR` and the four `SLOT_VARS` are never in a key: a leased directory or a slot count is not an input.
30. **Two amendments to ruling C-13 (R).** (1) Store a result only when the checkout is clean and at the **job's** tree (`outcome.tree`), not at `key.tree`: an inputs id is not a tree, so comparing against it would never store. (2) `usable_hits`: a later step's miss still forces the build step to run, but a build step's miss no longer voids later hits. A later step that hits needs no build; without this, a moved tree (which always misses the build step's key) would void every module hit and the inputs id would never pay off. With tree-id keys only, the amended rule gives the same answers as today (a build miss means the tree moved, so every later tree key misses too).
31. **The ls-tree read** runs once per tier job, only when at least one step is `per_module` and the job has a cache context, through `job.read` (the `GitQueue`, `--no-optional-locks`, the scrubbed environment; AGENTS.md rules 10 and 11). An error makes those steps keyless (a miss), never a wrong key. The tier-2 skip (`tier_cached.rs`) stays all or nothing and still misses whenever the build step does.

### Rulings on the design

The design research behind NA §3 (`m9.14.md` in the design gate) says, and this brief rules:

- **(R1) Decision 8, clean on release instead of "on owner change, in the new checkout".** The design runs `cargo metadata` in the new checkout before handing the lease over. For the ops that create a checkout (`PrepareWorktree`, `CreateRunBranch`, a proof's scratch, `TestAt`'s materialise) the new checkout does not exist yet when the lease must be decided, and their `setup` runs `cargo` right after creating it. Cleaning at release, in the outgoing checkout, always has a checkout to read, and still hands every new owner a directory free of the previous owner's path packages. Residual: a crate the outgoing checkout dropped from its workspace keeps its artifacts (risks).
- **(R2) Decision 9, substitution in the driver instead of "the leased path stored on the Run/Task model".** The pool is daemon-wide and shared by concurrent runs on one repository, so the engine cannot decide a lease purely; storing it on the model would need an extra op and result before every checkout's first op. Substituting in the driver keeps every builder pure, as the design wanted.
- **(R3) Decision 20, `Want::Half` for an interactive window**, which has no M9.1 cap to copy.
- **(R4) Decision 21, the wait is capped at `stall_after_secs / 2`.** The design did not relate the 300 s wait to the 600 s stall interrupt (`run/engine/clock.rs:112`).
- **(R5) Decision 26, `Step.per_module`.** The design's "steps whose affected key names modules" also matches the `check` step that stands in for module tests (`steps.rs:155`), which runs the whole suite and must keep the tree id (its decision 19).
- **(R6) Decision 30, both C-13 amendments.** The design keeps C-13 as is; as implemented, C-13 (1) would never store an inputs-id result and C-13 (2) would void every module hit whenever the tree moved, so the per-module key would never skip anything.
- **(R7) Decision 19 wording.** The design says agent asks "never delay engine work"; a granted hold does, until released (standing rule 5). The decision says what is true.

The controller's pre-flight rulings of 2026-10-12 (`.superpowers/sdd/M9.14-build-economy/preflight-scan.md`, accepted in the ledger; every line under "Implementation notes", "Pre-flight rulings") changed these decisions, each marked **(R)** in place:

- **(R8) Decision 1:** the profile reaches build outputs only through `$CARGO_TARGET_DIR` (C32).
- **(R9) Decision 2:** the default `task_dirs` is clamped to its range; a live `max_writers` change does not resize the pool (C26).
- **(R10) Decision 5:** the chosen directory's mutex is taken before a lease returns; the lease is saved before it is used, and a table loads lazily (C9, C10).
- **(R11) Decision 7:** a checkout that fell back stays on fallback until released (C24).
- **(R12) Decision 8:** the release is its own `await` outside the `GitQueue`; a gone checkout and a discarded run release not-cleaned; profile and triple directories are defined; the clean's environment empties the rustc wrappers; the clean's `ConfineSpec` grants the pool directory; any wipe leaves `Fresh` (C5, C6, C11, C12, C20, C21).
- **(R13) Decision 10:** `worker_git_dirs` appends `OpCtx.pool_grant` before it assigns the git grant (C1).
- **(R14) Decision 13:** the sweep re-checks and marks a directory before wiping it; `reconcile` spares leases made since the previous sweep (or since this daemon started); `restore` frees leases of unknown runs (C9, C10, C25).
- **(R15) Decision 14:** the table records `run` and `leased_at`; a lease is durable before use (C9, C10, C25).
- **(R16) Decision 17:** never the orchestrator's interactive window; no group when the wait is 0; the values plumbed through `ManagerConfig` → `LaunchContext` (C7, C22).
- **(R17) Decision 18:** a tokenizing matcher: more separators, wrappers, cargo aliases, toolchains and global flags; advisory (C13).
- **(R18) Decision 22:** `PostToolUseFailure` releases (F4); a newer `PreToolUse` releases a window's older holds; live means listed and not exited (C8).
- **(R19) Decision 23:** a per-connection cancellation token; insert before send; a re-check after a grant; "cannot be written" redefined (C2, C15, C16).
- **(R20) Decision 24:** `admit_hold_max_secs` defaults to 630 (C8).

### `cli`

`anthrex admit --window <id> --wait-secs <W> [--slots <n>] [--prefix <p>]…`, dispatched pre-clap (not in `--help`), payload on stdin. It reads at most `ADMIT_PAYLOAD_MAX` bytes; leaves at once (exit 0, no output, no connection) for anything but a `Bash` call with a `tool_use_id` and a heavy command (decision 18); otherwise connects, greets, sends `Admit`, and exits 0 on any reply, error or close. The whole process is bounded by `W + ADMIT_CLIENT_GRACE` from its start, in its main thread, as `hook.rs` bounds `HOOK_DEADLINE`.

### `fake-agent`

With `FAKE_AGENT_TOOL_IDS=1` in its environment, the `bash {cmd}` step gives each call the `tool_use_id` `fake-tu-<n>` (`n` counting from 1 per process) in its `PreToolUse` payload, and after the command runs every `PostToolUse` group that matches `Bash` with `{"hook_event_name":"PostToolUse","tool_name":"Bash","tool_use_id":…,"tool_input":{"command":…},"tool_response":{"stdout":…,"exit_code":…}}`. Without the variable the step is byte-for-byte today's. Independently of it, a hook entry's `timeout` (seconds), when present, replaces `STEP_TIMEOUT` for that hook.

## Risks and gotchas

- **Shared target dirs and compile-time paths** (from milestone 9.12's brief). `env!("CARGO_BIN_EXE_*")` and `env!("CARGO_TARGET_TMPDIR")` bake a build directory into a test binary, as `CARGO_MANIFEST_DIR` does (which 9.12 guards). Under the pool a binary built by one checkout can name another checkout's paths. Task M9.14.1 records the audit only (it changes no code, C28); a use that needed a guard would get it in M9.14.6, the first task that moves target directories, or become a follow-up. The audit ("Implementation notes", M9.14.1) found every use safe without a guard.

- **The task pool is smaller than two directories per writer.** A task worktree and its proof scratch are different owners (decision 4), so `max_writers` busy tasks want `2 × max_writers` task directories against `max_writers + 2` (U6). With the default 3 writers, a third task's proof scratch falls back to its own cold target (decision 7, one run log line). That is U6 as approved; record how often it happens in the end-to-end runs.
- **Disk.** Up to 140 GB per repository with the defaults (decision 15), enforced at release. A machine short of disk should lower `max_gb` or `task_dirs`, or set `enabled = false`.
- **A crate the outgoing checkout removed from its workspace keeps its artifacts** (ruling R1): its fingerprint is not in the clean list. A later owner that adds a crate of the same name and version with older sources could reuse them. Narrow; the integration checkout's engine directory never sees task artifacts (decision 6), so it cannot forge an engine verdict.
- **`cargo metadata --offline` fails without a warm registry**, which makes the clean a wipe: correct, only slower. A repository whose dependencies were never fetched on this machine wipes on every release until they are.
- **A pool directory is a write channel between tasks** in the task class. A worker can plant artifacts a later task's proof would use. Within a run, decision 6 confines the damage to task-level verdicts. **Across runs (C11):** the clean removes only path packages, so registry-dependency artifacts persist across owners, and merged worker code (build scripts, tests) runs in the integration checkout with the engine directory writable. A **discarded** run therefore releases every checkout not-cleaned, so each directory it used is wiped before its next lease; an **accepted** run's directories keep their warmth, since its code was accepted. Within a run the task class remains a channel, as above.
- **The release clean runs in a checkout a worker wrote (C12).** A rejected checkout can still hold a bounced `.cargo/config.toml` or `rust-toolchain*`. The clean empties `RUSTC_WRAPPER`, `RUSTC_WORKSPACE_WRAPPER` and `CARGO_BUILD_RUSTC_WRAPPER` and sets `RUSTUP_TOOLCHAIN` when known, and a discarded run's checkouts are not cleaned at all. Residual: other config `cargo metadata` honours (for example `build.rustc`) still runs, confined on macOS, unconfined on Linux or with unconfined checks.
- **Gate commands that hard-code `target/` (C32).** A profile whose commands or scripts read `./target/…` worked while `CARGO_TARGET_DIR` was `{worktree}/target`. Under the pool they read nothing, or a stale `target/` left by an earlier fallback build, which risks a false green. Decision 1 requires build outputs through `$CARGO_TARGET_DIR`; the optional refusal (`applies` false when a profile command holds a literal `target/`) is not taken.
- **An agent hold leaks when a `PostToolUse` is lost** (the status hook is best-effort with a 1 s deadline), or when an admitted call gets no `Post*` event at all (denied after the hook, refused, blocked by another hook, interrupted; C8). The window's next `PreToolUse` (`AllBut`), its `Stop`, the sweep (which also drops exited windows) and `admit_hold_max_secs` (630 s by default) bound it; a leaked hold delays engine steps by at most that long. A worker's turn spans its whole task, so `Stop` comes late.
- **A live `stall_after_secs` change leaves W stale (C31).** W is baked into the persisted spec at launch, so a later, lower `stall_after_secs` can let a wait reach the stall interrupt. Recorded, not handled.
- **The size measure can outlive its timeout (C33).** `POOL_MEASURE_TIMEOUT` abandons the walking thread rather than stopping it (the `bounded` pattern). Acceptable.
