# Milestone 9.19: Numbers unification

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (the user's standing choice) to implement this brief task by task, TDD. Steps use checkbox (`- [ ]`) syntax for tracking.

> **DRAFT, 2026-10-17, for the user's review.** Written from the numbers audit (`.superpowers/nucleos-design/numbers-audit.md`, "the audit" below), which read `main` at `636f0a40`. Every `file:line` below was re-read on `main` at `394a68fc` (milestone 9.18 merged, protocol 26, `RUN_FORMAT` 6, `HISTORY_VERSION` 5) and is relative to `crates/` unless the path says otherwise. Where the audit's line moved, the line here is the current one. One audit finding is already fixed and is dropped (see "Audit findings already fixed"). Choices that are the user's are listed at the end, under "Out of scope: needs the user", and nothing here decides them.

**Goal.** Every number anthrex shows, in the TUI, in the CLI (`status`, `run status`, `run stats`, `hold status`, `tree`), in the text the daemon renders (attention lines, `REPORT.md`, prompts) and in `?` help and the README, has one meaning, one label and one format, written down in one glossary (`docs/numbers.md`) that help and the README link to. "Tokens" always means billed tokens and the run's total covers design agents. Clock times a client shows are local with their offset; text the daemon writes is UTC; every clock time names its zone. One duration format and one age format. One definition of `merged/total` and of `stage k of m`. A missing value reads `unknown` (or `-` in a table cell), never `0`. Context fill never reads `450%`. Ages stop counting when the daemon link is lost. `hold status` says when a quota reading is stale, and `tree` says which number is the window id.

**Architecture.** A new pure module `common::numbers` holds every formatter, `common::progress` the shared counts, and `common::glossary` the glossary's terms. The TUI, the CLI and the daemon call them; their own copies are deleted. Display-only wherever possible: no wire type changes. One persisted field is added (the design agents' raw usage, so the run total can include them), which takes `RUN_FORMAT` 7 and `HISTORY_VERSION` 6.

**Tech stack.** Rust 2024 workspace; no new dependency (`common` stays on `proto`, `libc`, `anyhow`); `ratatui`'s `TestBackend` for render tests; `include_str!` for the glossary sync test.

**Integration-test paths.** As since milestone 9.12: `daemon/tests/it/<f>.rs` and `cli/tests/it/<f>.rs`, one binary per crate (`autotests = false`); a new file needs a `mod <f>;` line in `tests/it/main.rs`.

## Design decisions

1. **One module, pure, shared.** Every formatter named below lives in `common/src/numbers.rs`, every shared count in `common/src/progress.rs`, the glossary's terms in `common/src/glossary.rs`. They take integers and proto types and return `String`; none reads a clock, an environment variable or a file. The TUI (`ui/`, `inspector/`, `app/`), the CLI and the daemon call them. Each helper they replace is deleted, not wrapped. A task that cannot route a site through them records why under "Implementation notes".

2. **"Tokens" is billed tokens.** `tokens` everywhere is `input + cache_write + output` (`TokenUsage::billable`, `proto/src/run_info.rs:52`). Cache reads are not tokens; they show only as the cache share.
   - The three design sums use `usage.billable()`. `AgentSpend` gains `#[serde(default)] usage: TokenUsage` (the summed raw usage of its sessions) and `tokens` is `usage.billable()`. `run_usage` credits each `run.design.spend` agent's `usage` under `brainstormer` or `doc_reviewer`, so `RunUsage.total` covers every role (the M8c brief's promise). A format-6 `AgentSpend` (no `usage`) credits nothing: its stored `tokens` included cache reads and cannot be split. That undercount is accepted for runs designed before the upgrade and is said in CHANGELOG.
   - `PhaseAgent.tokens` is billed from `HISTORY_VERSION` 6. The design refit (`refit_design.rs:103-108`) takes token samples only from `phase` lines with `v >= 6`; calls and seconds still come from every line.
   - Format: `numbers::tokens` (today's `common::text::tokens`, unchanged): `999`, `4.5k`, `45k`, `1.2M`, floored. `REPORT.md`, the handoff lines and the TUI use it too; no raw token integer is printed outside `--json`.
   - Labels: the run spend row reads `tokens 1.8M (all roles) · cache hits 71% of input · worker tool calls 412`. The cache share keeps today's computation (`cache_read / (input + cache_read + cache_write)`, floored, omitted at a zero denominator). `run stats` heads its column `MED TOKENS` and the TUI `med tokens`; the glossary says "billed, worker + reviewer + decider of a merged task".
   - The `run stats` token median leaves out tasks whose billed tokens are 0 (as the refit does, ruling T8-5); a class with none left shows `-`.

3. **Clock times: local in the clients, UTC in daemon text, always labelled.** (User's choice, 2026-10-17.) Every clock time goes through `numbers::clock(at, now, offset_secs)`, a pure function; the zone label is `UTC` when `offset_secs` is 0 and the daemon wrote the text, else the offset `+02:00` / `-05:00`:
   - same day (in that zone) as `now`: `14:30 +02:00`;
   - within six days before or after: `Thu 14:30 +02:00`;
   - otherwise: `2026-10-12 14:30 +02:00`.
   `numbers::clock_full(at, offset_secs)` is always the long form.
   - **Clients (TUI, CLI) show local time.** Every time the TUI or the CLI formats itself (inspector, conversation view, alerts, `run status`, `hold status`, `profile`, the TUI's brake texts built from `common::brakes_text`) passes the viewer's offset.
   - **The daemon's own text stays UTC** and is labelled `UTC` (`14:30 UTC`): attention lines, brake texts the daemon composes, `REPORT.md`, agent prompts, the proposal file, the `REFIT` column. An agent prompt must not depend on the viewer's zone; 9.13 ruling C17 stands for these. `numbers::clock_utc(at, now)` is `clock(at, now, 0)` with the `UTC` label.
   - **The offset is read outside the pure code and refreshed.** `tui/src/lib.rs`'s `local_utc_offset_secs` becomes `common::localtime::offset_secs(at) -> i32` (the one place that calls `localtime_r`, returning `tm_gmtoff` as `i32`, no `as i64` truncation of a negative), called by the TUI's tick (the tick already passes `ticked_at`, `app/tick.rs:69`) and stored in `App.utc_offset_secs` every tick, so a DST change mid-session is picked up (fixes the read-once bug at `tui/src/lib.rs:94`). The CLI reads it once per command. Rendering stays pure: `ui/` and `app.rs` read `App.utc_offset_secs`, never the libc call. Past instants on the far side of a DST change print with today's offset; accepted and said in the glossary.
   - Deleted: both `local_hhmm`, `common::text::hh_mm`, the conversation's `clock` (all through `numbers::clock`).

4. **One duration format, one coarse form, one age.**
   - `numbers::duration(secs)`: `0s`–`59s`; `1m 00s`–`59m 59s`; `1h 00m`–`23h 59m`; `1d 00h` and up. Two units, the second zero-padded to two digits, one space, floored. Examples: `42s`, `41m 12s`, `1h 05m`, `3d 04h`.
   - `numbers::duration_coarse(secs)`: the largest unit only, floored: `42s`, `41m`, `1h`, `3d`. Only in fixed-width cells: the sidebar row's elapsed (`ui/tree_view.rs`'s `{elapsed:>3}`), the graph boxes and the alerts list's age column. The glossary says these cells round down to their unit.
   - `numbers::duration_ms(ms: u32)`: under 10 s, `4.2s` (tenths, floored); else `duration(ms / 1000)`; `u32::MAX` (the daemon's saturated value, `conversation/build.rs`) is `unknown`.
   - `numbers::ago(secs)`: `just now` under 10 s, else `<duration> ago`. Every "how long since" text uses it: `read 3m 10s ago`, `verified 2h 05m ago`, `updated 3d 01h ago`.
   - Minutes as a budget unit print `min` with a space: `numbers::budget_text` (moved from `text.rs`) prints `40 calls · 20 min · 200k tok`. Spend against it prints `duration(secs)` and the ceiling: `9m 40s of 10 min`.
   - Every floor stays a floor; stats `WORK MIN` floors (it rounded to nearest), and its header becomes `MED WORK` with `duration` cells. No display rounds up except the estimate (`est. left`, ceil, decision 14 of M9.5), which the glossary states.

5. **One progress count.** `common::progress::run_progress(&RunInfo) -> Progress` counts every round's tasks and leaves out of both numbers a task that is `Cancelled`, `Reported` (M9.2 review ruling 3) or has a non-empty `replaced_by` (M9.17). `merged` is the `Merged` ones. Shown `3/5 merged`; where a cell is too narrow (the sidebar tree row, graph boxes), `3/5 ✓`, with `✓ = merged` in the glossary. The inspector's `progress_text`, `tree::run_progress`, `graph::planner_text`, the CLI `run status` header and the Accept page fallback (`app/actions.rs:191-197`) all call it. `progress_text` keeps its categories and its `cancelled` count.

6. **No `0/0`.** While a run has no tasks (brainstorming, specifying, at a brainstorm or spec gate, planning), its overview title shows the same design word the graph node shows (`graph/run_text.rs`'s design text, e.g. `brainstorming · 7m`, `⏸ spec v2 · 7m`), never `0/0 merged`.

7. **Stage position.** `common::progress::stage_count(&RunInfo) -> usize` = the larger of the highest planned task stage and `run.stages.len()` (today's `run_stages`, `ui/alerts_detail.rs:34`, and `plan_stages`, `app/plan_summary.rs:36`, both deleted). Every position reads `stage k of m` with that `m`; `/` is kept for progress only (`stage 2/3` in `inspector/run_stage.rs` and `graph/run_text.rs` becomes `stage 2 of 3`).

8. **Stage counts follow decision 5.** The daemon's `StageInfo.tasks` (`daemon/src/run/snapshot_stages.rs`) counts the stage's tasks under decision 5's exclusions, so a stage can reach `n/n`. The wire field keeps its type; its value changes; an older client renders it the same way.

9. **Unknown is not zero.** `numbers::UNKNOWN` = `unknown` in a labelled field; a table cell prints `-`. Never `0`, `0s` or `0 changes` for a missing value:
   - A done or failed sub-agent with no `ended_secs`: `done` with no duration in the footer, the inspector (`for unknown`) and `tree` (`-`).
   - A profile row edit `Failed` with `secs == 0` and an empty `tail` (written only by `profile/row_edit.rs:225`, `:250` and `profile/service_restore.rs:248`, when the check never ran): a bare `✗ did not run`. Display-only; the wire type stays.
   - The doc gate's narrow row while `gate` is `None` (`ui/doc_gate_panes.rs:20`): `loading…`.
   - Any age while `runs.now == 0` (no snapshot yet): the age is left out (`Ready`, not `Ready · verified 0s ago`).
   - The idle orchestrator's `runs` row (`inspector/run.rs:186`): the real count, `0` included (it is a real zero).

10. **Percentages never pass 100 silently.** `numbers::fill(tokens, window) -> Fill { Percent(u8) | Over | NoWindow }`, `numbers::context_text(tokens, window: Option<u64>)`:
    - `context 92% full (183k / 200k)`;
    - over the window: `context over 100% (450k / 200k window)`;
    - no window or a zero window: `context 183k (window unknown)`.
    The daemon's handoff and attention lines (`contract_rounds.rs:221`, `:241`, `:253`, `orch_fill.rs`) and the TUI's handoff row (`inspector/run_orch.rs:141-145`) use it. The handoff trigger (`fill.rs:99`) and `fill_percent` for thresholds are unchanged. `numbers::busy(busy, max)` prints `2/3`, or `4/3 (over)` after a mid-run limit change (`writers`, `readers`, CLI and TUI).

11. **Values freeze when the link is lost.** `App` gains `frozen_at: Option<Instant>`, set by `on_link_lost` and cleared by the first snapshot after a reconnect. `age_secs` and `run_now` measure to `frozen_at` when it is set, so no age, timer or `est. left`-beside-age pair moves while disconnected. While frozen, the sidebar footer, the git segment and the alert ages draw in the muted role, and the ` DISCONNECTED ` badge reads ` DISCONNECTED · as of <ago> `. The model picker's age is `run_now() - fetched_at` through `ago` (the `received_at` list is deleted). Rendering stays pure: the instant is passed in by the tick, as `ticked_at` is today (`app/tick.rs:69`).

12. **`hold status` tells the truth.** `quota_line` matches `quota.state`:
    - `Fresh`: `claude quota: 5h 42% · 7d 63% (read 3m 10s ago) · not braked`;
    - `Stale`: `claude quota: 5h 42% · 7d 63% (stale: read 1h 35m ago) · not braked`;
    - `Unmeasured`: `claude quota: unmeasured · not braked`;
    - `Braked`: the windows, then `· ` and `common::brakes_text::quota_held_text`, whose time goes through `numbers::clock` with the viewer's offset (`… until Thu 14:30 +02:00`).
    The hold line reads `hold: on since Thu 14:30 +02:00 (2h 05m ago) (<by>)`.

13. **`tree` labels its numbers.** A window row reads `  #1  id 7  <name>  <runtime>  <model>  <status> <duration>`: `#` is the position `C-b <n>` uses, `id` is the id `ls`, `kill` and `attach` take. The counts read `claude 2 · codex 1 · shell 1` (as `--json` names them). A sub-agent's time reads `running 3m 10s`, `ran 12s`, or `done -`.

14. **`run stats` labels its aggregates.** Headers `TASKS MERGED MED LINES MED CALLS MED TOKENS MED WORK BOUNCES (ALL) REVERTED`, and a footer line `MED = median over merged tasks · tokens are billed (worker + reviewer + decider) · BOUNCES counts every task`. The rounds line reads `rounds: 3 ended · 1 run iterated` (pluralised). The TUI stats page uses the same words in lower case and shows the rounds line.

15. **The glossary binds.** `docs/numbers.md` holds the glossary below verbatim. `common::glossary::GLOSSARY` lists the same terms, in the same order, with a one-line definition each. `?` help gains a `numbers` group drawn from `GLOSSARY`. The README gains a "Reading the numbers" section of three sentences that links `docs/numbers.md`. A term whose code deviations are deferred (see "Scope", Out) is marked `(not yet unified)` in the doc only.

## Glossary (the content of `docs/numbers.md`)

| Term | Shown as | Unit, format, rounding | Definition |
|---|---|---|---|
| tokens | `tokens 1.8M` | `999`, `4.5k`, `45k`, `1.2M`; floor | Billed tokens: input + cache writes + output. Cache reads excluded. A run's total covers every role, design agents included. |
| cache hits | `cache hits 71% of input` | %; floor | Cache reads ÷ (input + cache reads + cache writes). Not a share of tokens. |
| context | `context 92% full (183k / 200k)` | % of the window; floor; `over 100%` past it | The last main-chain turn's tokens, cache reads and output included (Codex: last input + output), over the session's window. Not the same number as tokens. |
| window | `200k window` | tokens | Config above 0 wins; else Codex's rollout window, Claude `[1m]` → 1M, the learned window, else 200k. |
| quota | `5h 42% · 7d 63%` | %; floor | The runtime's own reported use of its rolling window; `stale` when older than `quota_fresh_secs`. |
| duration | `42s`, `41m 12s`, `1h 05m`, `3d 04h` | two units; floor | A span: run time, check time, tier time, how long an agent ran. Fixed-width cells show the largest unit only (`41m`). |
| age | `3m 10s ago`, `just now` | a duration; floor | Now minus when it happened, on the daemon's clock. Frozen while the daemon link is lost. |
| clock time | `14:30 +02:00`, `Thu 14:30 +02:00`, `2026-10-12 14:30 UTC` | local offset, or UTC | Always labelled with its zone. The TUI and CLI show your local time with its offset; text the daemon writes (attention lines, `REPORT.md`, prompts) is UTC. A weekday within six days, a date beyond. Past times across a DST change use today's offset. |
| merged | `3/5 merged`, `3/5 ✓` | tasks | Merged tasks over tasks that can still merge: cancelled, replaced and reported tasks are in neither number. All rounds. |
| stage | `stage 2 of 3` | stages | The task's stage over the larger of the planned stages and the recorded ones. |
| round | `round 2` | goal rounds | One `run iterate` request and the tasks planned for it. |
| session | `worker #2` | count | One launch of an agent on a task. (not yet unified) |
| review | `review 2` | count | The nth review verdict on a task. (not yet unified) |
| bounces | `review 1/3` | per gate | A gate failure sent back to the same session, over the run's `max_bounces`. |
| escalation step | `step 2` | 1–4 | 1 send back, 2 fresh session, 3 size raised, 4 block. |
| budget | `40 calls · 20 min · 200k tok` | per session | A ceiling per worker session; soft at 1×, hard at 1.5× on any axis. Spend is kept in seconds. |
| est. left | `est. left ~40m` | duration; ceil | Time left in the current round, after approval, from history's weights. The one value rounded up. |
| bound ratio | `1.2× the bound` | ×; floor | (active elapsed + est. left) ÷ the round's fastest possible time from history's weights. |
