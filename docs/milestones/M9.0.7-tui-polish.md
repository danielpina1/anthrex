## Global Constraints

These bind every task. A reviewer rejects a change that breaks one, whatever the task text says.

1. **No protocol change.** `crates/proto`, `crates/daemon`, `crates/config` and `crates/cli/src` are untouched (`git diff --stat <base> -- crates/proto crates/daemon crates/config crates/cli/src` prints nothing, `<base>` being `4e8c9d9`, the 9.0.6 branch head, until PR #28 merges, then `main`). Anything the screens would like to show that the snapshot does not carry is drawn as absent, never invented, and is listed under "Out of scope".
2. **The client's state stays pure** (AGENTS.md rule 5). `app/**` and `ui/**` do no I/O; every update returns `Vec<Effect>`; every renderer takes `&App`. Time comes from `App::run_now`/`run_age` (the snapshot's daemon clock) and `App::elapsed_secs` (the window list's), never from a fresh `SystemTime::now()` in a renderer.
3. **Principles 1–10 of §5.1 bind every screen touched.** In particular: one accented frame (decision 1); `⚑` in `Attention` is "needs you" and nothing else is (principle 1); roles, not RGB values (principle 3); one glyph, one meaning, each with its ASCII twin (principle 4, decision 6); one name per object (`kit::run_name_in`, principle 5); hints drop whole and keep `esc` (principle 8); one dialog grammar (principle 9).
4. **Every displayed string passes `safe_text`** (M9.0.6 Global Constraint 7): a row through `safe_text::one_line`, a pane through `multi_line` then `one_line` per wrapped line, or through a kit widget that does it. Every new renderer has a hostile-text test with `safe_text::tests::hostile_text()` / `first_hostile`.
5. **Real render tests.** Every screen task tests with `ratatui::backend::TestBackend` at 80×24 and 120×40 with exact rows (trimmed of trailing spaces where the brief says so), once with `UiSettings.badges.ascii = true`, and at 20×5, 1×1 and 5×40 for no panic. The audit module of task 2 is the shared harness.
6. **Tests never reach real agents.** Everything here is a reducer or render test over hand-built `RunInfo`/`WindowInfo` fixtures; no test starts a daemon except the smoke script, which pins every `*_BIN` to `fake-agent` as it already does. A wait in the smoke script is a deadline loop, never a bare sleep (AGENTS.md rule 6); render tests have no clock (ages are set through the snapshot's `now` and `App::set_runs_received_at`, `app/runs.rs:442`).
7. **Files stay under about 600 lines** (rule 8). "File sizes this milestone must respect" gives each touched file's bound; new files stay under 600.
8. **Never touch a live daemon** (rule 1): the manual check sets `ANTHREX_SOCKET`, `ANTHREX_DATA_DIR` and `ANTHREX_CONFIG` under `/tmp` and ends with `anthrex daemon stop`.
9. **Changed expectations are named.** A pre-existing test whose expected rows change because the spec changes them is updated in place in the task that changes them, and its name is listed under that task's "Implementation notes" entry. A test is never deleted to make room; a test file at its bound gets a sibling file. Task 1's results list the tests each decision's text change reaches ("Task 1 results", step 5).
10. **Clippy is CI's stable, 1.99.** Before every commit, `cargo +1.99 clippy -p <touched crates> --all-targets -- -D warnings`, also with `--target x86_64-unknown-linux-gnu` (CI runs macOS and Linux); the code keeps compiling on 1.98 (`cargo +1.98 check`), so a lint fix never uses an API newer than 1.98 (the 9.0.6 branch's `4e8c9d9` allowed `fetch_update` rather than use 1.99's `try_update`).

## Goal

At 80×24 and 120×40, in colour and in ASCII, every screen of the client shows its state word, its outcome and its next key without scrolling, and exactly one frame is accented: the one the keys reach. The Alerts box under the agents takes the free rows of the sidebar column, each alert in two lines — who it is for (`Add mul() · 0723 › t2  41s`) and what happened, wrapped — and `C-b a` opens a full Alerts view in the main pane with the alert's whole text, its run, task, agent and age, and its actions, Enter on the one that fits. The task panel reads OUTCOME (the pipeline, the check, the acceptance criteria), EVIDENCE (the diff and the review), INTENT (the brief, one line), then the rest, with a footer naming the stage, route, size and test mode. The run view's inspector takes the rows its node needs; below 30 rows the graph becomes a one-line-a-node list with each node's state and deps; a red stage reads `✗ bisecting`, never a spinner. The plan review is framed, opens on a summary (tasks, stages, sizes, budget, critical path, overlap warnings) and lists tasks in aligned columns whose deps survive at 80 columns. Sidebar overflow is marked, pane titles read `sh shell-1 · ~/repo`, the status bar has a badge per mode, help is grouped and scrolls, and every old dialog speaks the kit's grammar.

### One accented frame, and the frame every pane draws (§5.1 principle 2, §6.9)
