> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (the user's standing choice) to implement this brief task by task, TDD. Steps use checkbox (`- [ ]`) syntax for tracking.

> **DRAFT, 2026-10-15, for the user's review.** Written from `docs/superpowers/plans/2026-09-17-anthrex-foundation-followups.md` ("the follow-ups file" below) only: every task closes an entry already written there, quoted by its heading and its line on `main` at `bac2aa9e` (milestone 9.15 merged, protocol 24, `RUN_FORMAT` 4). No task adds a product feature. Entries that need a user decision, a design-rule change or a change to process-ending code are listed at the end, under "Out of scope: needs the user", and nothing here touches them. Every `file:line` below was read at `bac2aa9e` and is relative to `crates/` unless the path says otherwise. This milestone is built **after milestone 9.17 merges**; 9.16 and 9.17 will move some of these lines, so task M9.18.1 re-reads every anchor on the merged `main` first and records what moved.

**Goal.** No new behaviour, fewer known defects. A Stripe key, an AWS secret, a `Basic` credential or an encoded URL password no longer reaches a provider prompt or the Lessons page. A `timeout 600 cargo test` waits for its slots like a bare `cargo test`. A `CARGO_PROFILE_*` change can no longer reuse a cached green built another way. `lessons.jsonl` stops carrying lines no reader needs, and moved-aside `tuning.toml` files stop piling up. A wheel scroll over an orchestrator window no longer leaves a wake-up pasted and unsubmitted. A failed tool call closes in the conversation view when it fails, not when the transcript catches up. Rung 4 never lowers a task's own budget, a CJK path no longer breaks a dialog box, and four hand-written source rules lose their known holes. Every production and test file the follow-ups file names as over 600 lines is split.

**Architecture.** Twelve independent tasks; none depends on another except that M9.18.2's move-only splits come before any task that edits the same file. No wire type changes, no persisted `Run` field is added, no `LessonLine` variant changes.

**Tech stack.** Rust 2024 workspace; `regex` (already used by `lessons/redact.rs`); `unicode-width` (already a `tui` dependency, `tui/Cargo.toml:25`); real temporary directories and the real daemon for the I/O tasks; `fake-agent` for every agent.

**Integration-test paths.** As since milestone 9.12: `daemon/tests/it/<f>.rs` and `cli/tests/it/<f>.rs`, one binary per crate (`autotests = false`); a new file needs a `mod <f>;` line in `tests/it/main.rs`. `source_rules::every_integration_test_file_is_compiled` fails on a file no target compiles.

## Design decisions

1. **One theme, no features.** Each task closes one follow-ups entry, or a group the entry itself names together. A task that turns out to need a protocol field, a new persisted field, a config key or a user-visible text not quoted below stops, records the evidence under "Implementation notes", and the other tasks continue.
2. **Move-only first.** A split is its own commit, with no change of code, and the test count before and after recorded (the memory rule "verify move commits by test count"). A file this milestone edits that is within 10 lines of 600 is split before the edit.
3. **Compaction keeps the fold.** `lessons::store::compact` rewrites `lessons.jsonl` keeping every line except (a) an `attempt` line whose entry has a `distilled` or `gave_up` line in the file, and (b) an earlier line whose `record_id` a later line that parses repeats. A line that does not parse is kept verbatim, in place (it may be a newer anthrex's). The acceptance test is `fold(after) == fold(before)` with each closed entry's `attempts` set to 0 on both sides; `attempts` is read only for open entries (`service.rs:281`, `:320`, `:333`).
4. **When compaction runs.** In `Worker::serve`, under the repository's `LessonLocks` entry, on `spawn_blocking`, when the store is at least `LESSONS_COMPACT_BYTES` = 1 MiB **and** the compaction would drop at least a quarter of its lines. The rewrite is `write_atomic` (temporary file, `sync_all`, rename), so a lock-free reader reads the whole old file or the whole new one. A failed compaction is a `tracing::warn!` and leaves the file as it was.
5. **`tuning.toml.bad-*`.** When `tuning_io::load` moves a file aside, it then removes every `tuning.toml.bad-*` in the directory except the newest `TUNING_BAD_KEEP` = 3 by the `<unix secs>[-n]` in their names (a name that does not parse is never removed). A failed removal is ignored.
6. **Redaction stays best-effort (9.15 decision 11).** The new shapes, each replaced by the existing markers (`TOKEN`, `USERINFO`):
   - `sk_live_` and `sk_test_` join the unambiguous prefixes, with the body alphabet `[A-Za-z0-9]` and the existing `UNAMBIGUOUS_BODY_MIN` (4) and uppercase-or-digit rule.
   - An AWS secret access key: a run of exactly 40 characters of `[A-Za-z0-9/+]` holding a digit, an uppercase and a lowercase letter, (a) after a key name `aws_secret_access_key`, `secret_access_key` or `SecretAccessKey` (any case) and `=` or `:` with optional spaces and quotes, or (b) on the same line as an `AKIA` access key id. Rule (b) runs before `prefixed`, which replaces the id.
   - `Basic` (any case) then whitespace then a base64 run of 8 or more characters whose decoding is UTF-8 holding a `:` becomes `Basic [redacted]` (the new marker `BASIC`). "Basic usage" is left alone.
   - URL user information spelled with `%3A%2F%2F` (any case) or `:\/\/` for `://`, and `%40` for `@`, is replaced as `URL_USERINFO` replaces the plain spelling, the scheme kept as it was spelled.
   A residual the review listed that already passes on `main` gets a pinning test, recorded as such.
7. **The heavy matcher's additions (9.14 decision 18 stays fail-open).** `timeout` and `stdbuf` join `COMMAND_WRAPPERS`. A wrapper may take positional words: `timeout` skips one (its duration) after its options; `stdbuf` none. Their options with a value: `timeout -s`, `--signal`, `-k`, `--kill-after`; `stdbuf -i`, `-o`, `-e` (and the attached `-oL` and `--output=L` forms take nothing more). The cargo plugin subcommands `llvm-cov`, `miri` and `hack` are heavy whatever follows; `insta` is heavy only as `insta test`.
8. **The cache key's environment (9.14 decision 29).** Besides `TOOLCHAIN_ENV_VARS`, every variable named `CARGO_PROFILE_*`, `CARGO_TARGET_*_RUSTFLAGS`, plus `CARGO_BUILD_RUSTFLAGS` and `CARGO_INCREMENTAL`, counts, sorted by name, the step env's value winning over the daemon's. When none is set, the key is byte-for-byte today's. The pure core takes the daemon's matching variables as a list, which `with_env` reads from `std::env::vars()`; no test sets a process variable.
9. **Saturation and the rung 4 floor.** The four token sums use `saturating_add`. Rung 4's `own` is, per axis, the larger of the class's budget and the task's `budget` (tokens: the larger when both are set, the one that is set otherwise). `refit::ceiling` is unchanged.
10. **What counts as typing.** `write_client_input` notes client input unless the bytes are entirely complete mouse reports: SGR (`ESC [ <` digits `;` digits `;` digits then `M` or `m`), URXVT (`ESC [` digits `;` digits `;` digits `M`) and the default and UTF-8 encodings (`ESC [ M` then three characters). Anything else, cursor keys included (the wheel on an alternate screen without a mouse mode sends them, and they move a prompt's history), stays client input. The bytes are written either way. The classifier is pure, in `manager/input_kind.rs`.
11. **The graph's module bound.** `modules_at`'s profile fallback walks with a deadline of `GRAPH_MODULES_BOUND` = 2 s (`common/src/bounds.rs`, beside `LESSONS_START_BOUND`), checked between `read_dir` calls; past it the source is `ModuleSource::None` with no modules, as when there is no profile. The tier code's own call to `module_dirs` (`verify_tiers.rs:175`) is unchanged.
12. **Display columns.** `dialog::wrap` measures with `unicode_width::UnicodeWidthStr` and hard-cuts a wide word at a character boundary whose width fits; a character wider than the whole line is placed alone on its line.
13. **A failed tool call.** `ParsedHook` gains `error: Option<String>` (Claude's `PostToolUseFailure` payload field, 9.14 fact F4) and `is_interrupt: Option<bool>`. `apply` handles `PostToolUseFailure` as `post_tool_use` would handle a `tool_response` of `{"error": <error>}`, with the summary `interrupted` when `is_interrupt` is true and `error` is empty. The transcript reader's later result for the same call replaces it exactly as it replaces a `PostToolUse` result today. The handler lives in a new `conversation/build_failure.rs` (`build.rs` is 588 lines).
14. **`fake-agent` follows the real CLI.** A `bash` step that exits non-zero fires `PostToolUseFailure` with `error` (its stderr's first line, or `exit status <n>`) instead of `PostToolUse` (9.14 fact F4). A test that relied on the old event is fixed to expect the new one and listed in "Implementation notes".
15. **The source rules' holes.** (a) Only `tests/fixtures/` at a crate's root is exempt. (b) The crate list is every `crates/*/Cargo.toml` that sets `autotests = false`. (c) The guard wants `checkout_dir(` preceded by `::` or a non-identifier byte. (d) A `mod x;` under a `#[cfg(…)]` other than `test`, `unix`, `target_os = …` or `not(test)` paired with a `test` twin counts as a hit to review, failing with its line. (e) A `mod b;` inside an inline `mod a { … }` in `x.rs` resolves to `x/a/b.rs`. A new rule `the_target_pool_pure_files_are_pure` fails on `std::fs`, `std::process`, `std::net`, `std::thread`, `tokio::`, `Command::new`, `SystemTime` or `Instant::now` in `run/target_pool/{book,book_file,clean}.rs`, as the 9.14 Verification grep does by hand.

## Risks and gotchas

- **Compaction races an append.** Every writer must hold `LessonLocks` (M9.18.1 step 3 checks it). A writer found without it stops compaction; do not "fix" it by taking the lock in compaction alone.
- **A newer anthrex's lines.** Compaction must never drop a line it cannot parse, and must keep its position; a `v` higher than this binary's is such a line.
- **Redaction over-matches.** The `Basic` rule decodes base64; keep the decode bounded by the run's length (it is linear) and never decode across whitespace. The AWS rule (b) replaces any 40-character mixed-case run on an `AKIA` line: accepted over-redaction, as 9.15's own rules accept.
- **The matcher's positional skip.** `timeout` with an option whose value looks like a duration (`-k 5 60`) must skip the option's value and then exactly one positional. A test pins it.
- **Cache keys move once.** Users with `CARGO_PROFILE_*` or `CARGO_INCREMENTAL` set see their next tier run miss the cache once. That is the fix, not a regression; say so in CHANGELOG.
- **Mouse report shapes.** A paste that happens to begin with `ESC [ <` and ends in `M` is not a complete report unless every byte matches the grammar; the classifier must be strict, or a typed paste could be submitted under the user's keys.
- **`fake-agent`'s event change.** Tests across `daemon` and `cli` read `fake-agent`'s hooks; run the whole suite after M9.18.11, not only the touched files, and list each test that changed.
- **macOS first-exec stall.** M9.18.8's and M9.18.11's integration tests exec stand-ins; warm them as `docs/timing-budgets.md` describes, and wait with deadline loops.
