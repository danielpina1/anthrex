**Goal.** anthrex stops starting new agent sessions when the user's subscription is nearly used up, lets the user stop all new sessions with one switch, and moves a long-lived orchestrator to a fresh session at a goal boundary before its context fills up. Sessions already running are never killed.

**Architecture.** Three brakes, one gate. The **quota brake** reads the usage figures the CLIs already print — Claude's `rate_limit_event` stream line and the `token_count` lines in a Codex session's own rollout file — into a pure `QuotaBook` in the engine state. The **hold** is a daemon-wide switch persisted in `<data_dir>/brakes.json`. Both feed one pure `brakes::Gate` that the scheduler's new-session entry points consult per runtime. The **context handoff** measures the orchestrator's context fill from its own transcript tail when a goal continues a chain, and starts a fresh session (milestone 9.3 decision 24's path) instead of adopting the old window once the fill crosses the threshold.

**Tech stack.** Rust 2024 workspace; `serde`/`rmp-serde` wire types; `ratatui`/`crossterm` for the TUI; `fake-agent` for every test.

**Spec.** NA §5 and the decisions U11–U13 in NA §1.1. Read both before task M9.15.2. NA §5 is a summary; the detail it leaves open is decided below, each ruling marked **(R)**. Where this brief cites "NA §5 A<n>", "B<n>", "C<n>" or "Protocol impact", it means the numbered points of the approved design research that NA §5 condenses (`.superpowers/nucleos-design/m9.15.md`, outside the repository: A the context handoff, B the quota brake, C the global hold); each point this milestone relies on is restated in full in the decision that cites it, so the brief stands without that file.

## The user's decisions

These bind every decision here (NA §1.1, recorded from the user's design gate of 2026-10-10) and are never reinterpreted:

- **U11** The quota brake is **on by default**, pausing at **90 % of the 5-hour window** and **95 % of the 7-day window**.
- **U11** (continued) Readings come **only** from the CLIs' own output: Claude's stream `rate_limit_event` and Codex's rollout. The daemon **never** reads an OAuth token, `~/.claude/.credentials.json` or the macOS Keychain, and makes no HTTP request to a vendor.
- **U12** The hold stops **new sessions only**. Merges, delivery (pushes, pull requests, CI and review polling), gates and every open turn continue.
- **U13** The handoff fires at **whichever comes first: 80 % of the context window or 300,000 tokens**. Both are configurable; 0 disables. A **Codex orchestrator also hands off automatically** when its rollout gives a fill.

## Goal

When a runtime's subscription window reaches its threshold, no new session of that runtime starts anywhere in the daemon until the window resets or a fresher reading shows it below; tasks already running keep their reviewers and fix rounds. `anthrex hold on` (or `C-b H`) stops every new session of every runtime until `anthrex hold off`, across daemon restarts, without pausing any run. A goal continued on a chain whose orchestrator's context is past the threshold starts with a fresh orchestrator session that is told what came before, and the old window stays open for the user to close.

### Facts and units

1. **Fixtures are captured by the controller, never by the implementer.** Every new fixture in M9.15.1 is captured by the human or controller with the real `claude` and `codex` on `PATH` and checked in with a `.meta.json` (`{"runtime", "cli_version", "captured", "redactions"}`, the existing convention). Tests read only checked-in fixtures and drive only `fake-agent`. Where a capture has not landed, the tests named here use the existing fixtures listed in "Starting point", which already carry every shape this milestone parses except Codex's 5-hour window and a `[1m]` `modelUsage` key.
2. **One canonical unit: per mille, as `proto::brakes::Permille(u16)`, 0 to 1000.** Claude reports a **fraction** (`utilization: 0.53`), Codex a **percentage** (`used_percent: 99.0`). They are converted in exactly one place, `Permille::from_fraction(f64)` and `Permille::from_percent(f64)` in `proto/src/brakes.rs`, the only two functions in the workspace that multiply a usage figure: `from_fraction(x) = round(x × 1000)`, `from_percent(p) = round(p × 10)`, each clamped to 0..=1000, and `None` for a NaN, an infinity or a negative value (an unmeasurable reading, never a wrong one). Every threshold comparison is `used.0 >= u16::from(percent) * 10`. **(R)** NA §5 keeps `used: f64`; `RunsSnapshot` and `RunInfo` derive `Eq`, which an `f64` cannot, and an integer cannot be mistaken for the other unit. Displayed percentages are `used.0 / 10` (floor).
3. **Two windows**, `QuotaWindow::{FiveHour, SevenDay}`, wire `five_hour` / `seven_day`, labels `5h` / `7d`, lengths `FIVE_HOUR_SECS = 18_000` and `SEVEN_DAY_SECS = 604_800`. Claude: `rate_limit_info.unifiedWindows.five_hour` / `seven_day`, each `{utilization, resetsAt}`. Codex: `rate_limits.primary` and `rate_limits.secondary`, each `{used_percent, window_minutes, resets_at}`, mapped **by `window_minutes`** (300 → `FiveHour`, 10080 → `SevenDay`), never by position: the checked-in rollout has its 7-day window as `primary` and `secondary: null`. Any other window or key is ignored.

### The quota brake (NA §5 B)

4. **`SessionEvent::Quota(QuotaSample)`** from a Claude `rate_limit_event` line: `QuotaSample { windows: Vec<(QuotaWindow, Permille, Option<u64> /* resets_at */)>, rejected: Option<QuotaWindow> }`. `rejected` is set when `rate_limit_info.status == "rejected"`, to the window `rateLimitType` names (`five_hour` / `seven_day`); that window then counts as 1000 ‰ whatever its `utilization`. `allowed` and `allowed_warning` change nothing (the utilization decides). A line with no usable window yields `SessionEvent::Other { kind: "rate_limit_event" }` as today. The parser stays pure; the reading's time is the engine event's `now`.
5. **Codex readings come from the session's own rollout.** On a headless Codex window's `TurnEnded`, the driver reads the tail of that session's rollout (decision 9) for the last `event_msg` whose `payload.type == "token_count"` and turns its `rate_limits` into a `QuotaSample` (`transcript/fill.rs::codex_limits`). At most one rollout read per `ROLLOUT_READ_EVERY = 60 s` daemon-wide, so many Codex workers do not each read a file per turn.
6. **The `QuotaBook`** (`run/engine/quota_book.rs`, pure) lives in `EngineState.brakes`, daemon-wide, one entry per runtime, fed by `EventKind::Quota { runtime, sample }`. **(R)** NA §5 says "on the run service": the engine owns the gate, so the book is engine state (in memory, never persisted; a restart starts unmeasured, decision 8). For each window it keeps the newest reading `{used, resets_at, read_at}`. A reading at or over its threshold **trips** the window: `Trip { window, used, threshold_percent, until, read_at }` with `until = resets_at` or, when absent, `read_at + window length`.
7. **Release (the deadlock guard, NA §5 B4).** While braked no session of that runtime runs, so no new reading arrives. A trip is cleared only when `now >= until`, or when a reading of that window **newer than the trip's** is below the threshold. A trip never clears because its reading went stale.
8. **Fail open (NA §5 B5).** With no trip, dispatch is allowed: also when there is no reading or the newest is older than `quota_fresh_secs`. That state is `QuotaState::Unmeasured` (no reading since the daemon started) or `Stale`. The first time per daemon start that the gate lets a session of a runtime start while that runtime is `Unmeasured` or `Stale` and the brake is enabled, the engine logs to that run `<runtime> quota is unmeasured; dispatch is not braked` (`QUOTA_BLIND_TEXT`), once per runtime (`Brakes.announced`).
9. **Locating a rollout.** The rollout of thread `<id>` is the one file whose name ends `-<id>.jsonl` in `<sessions>/<YYYY>/<MM>/<DD>/`, where `<sessions>` is `transcript::rollout::codex_sessions_dir` and the dates searched are the session start's date and the day before and after (three directories listed, no recursive walk), cached per thread once found. **(R)** NA §5 says "reads the targeted file and walks no directories": the file name carries a timestamp the daemon does not know, so one listing per candidate day is the least that finds it. M9.15.1 confirms the name shape and whether the date directories are local time or UTC.
10. **Config** (`[orchestrator.brakes]`, settings-owned, applied live): `quota_brake = true`, `quota_pause_5h_percent = 90` (1..=100), `quota_pause_7d_percent = 95` (1..=100), `quota_fresh_secs = 600` (60..=86_400). **(R)** NA §5 names the table `[brakes]`; every settings-owned key today is under `[orchestrator]` and the settings code (`doc_of`, `apply_owned`, `changed_since_loaded`, `swap_owned`) is built on `config::Orchestrator`, so the table is the sub-table `[orchestrator.brakes]`, as `[orchestrator.design]` is. After every config load and every settings save, the driver sends `EventKind::BrakesConfig(BrakeConfig)`; on it the book re-derives every trip from its stored readings under the new thresholds.
11. **What the gate stops (NA §5 B3).** Gated, per runtime: `dispatch_writers` (a task skipped stays `Queued`), `launch_ready` (a `Preparing` task keeps its `ready_from` and waits), `kinds::dispatch` (both calls), and `planners::dispatch`'s three starters (sub-planners, design agents, run scouts; a candidate whose route's runtime is refused stays queued, the next one is tried). Not gated: `restore::relaunch`, `pair::launch_due` (a paired task's implementer is the second session of an already-dispatched task: in-flight work, controller ruling 2026-10-10), deciders (`deciders::dispatch`), reviewers and gates of tasks already dispatched (`review::dispatch_reviewers`, `gates::start_gates`), fix rounds of running tasks, merges, delivery, orchestrator wakes and relaunches. The runtime of a task is `pair::dispatch_runtime(run, i)`; of a planner, design agent or scout its route's runtime. Race lanes (`lane_passes`) use the same gate.
12. **The gate is separate from milestone 9.5's caps** and does not touch `RunConcurrency`, `rate_limits` or the estimates. `concurrency::has_room` still applies after it.
13. **Visibility (NA §5 B6).** A non-terminal run with a `Queued` or `Preparing` task (or a queued planner, design agent or scout) on a braked runtime has the attention line `<runtime> dispatch held: <window> at <n>% (≥<t>%) until <HH:MM> UTC` (`quota_held_text`; `HH:MM` from `orch/contract_messages.rs::hh_mm`, moved to `run/orch/clock_text.rs` as `pub(crate)`). **(R)** NA §5 writes `until 14:30` without a zone; every daemon-written time today is UTC (`hh_mm`'s doc). The snapshot carries `RunsSnapshot.brakes`; the TUI raises one `DispatchHeld` alert (decision 31); `anthrex hold status` and `anthrex run status` print it (decision 34).
14. **Revision.** `step` computes `brakes::info(&state.brakes, now)` before and after the event; a difference bumps `state.revision` exactly as `chains_moved` does in `finish` (`engine/mod.rs:379-406`), so a trip, a release at `until` on a `Tick`, or a hold change republishes the snapshot.

### The hold (NA §5 C)

15. **`DispatchHold { since: u64, by: String }`**; `BrakesInfo.hold: Option<DispatchHold>` (`None` is off). `by` is `"user"` for a request, `"corrupt brakes.json"` or `"unreadable brakes.json"` when decision 16 fails closed. **(R)** NA §5 writes `Hold { on, since, by }`; `proto::orch::HoldInfo` already names a plan approval hold, and an `Option` cannot hold `on: false` with a `since`.
16. **`<data_dir>/brakes.json`** = `{"v": 1, "hold": {"since": <u64>, "by": "<text>"}}` or `{"v": 1, "hold": null}`. Written by `run/driver/brakes_io.rs::save` on `spawn_blocking` within `BRAKES_IO_WAIT = 5 s`: a temp file in the same directory, mode 0600, `fsync`, rename. Loaded once at `RunService` start the same way. Missing: hold off. Unparseable or `v != 1`: renamed to `brakes.json.corrupt-<unix>` and **hold on** with `by = "corrupt brakes.json"` (fail closed: the user asked for it). A read error or a read that does not finish in time: hold on with `by = "unreadable brakes.json"`, logged; the file is left as it is. Never in `state.json`.
17. **The request.** `RunRequest::Hold { on: bool }`, answered under `request::HOLD = "hold"` with `RunReply::Held { hold: Option<DispatchHold>, message: String, request_id }`. The driver writes the file first; if the write fails the request is refused (`RunReply::Refused`, `the hold was not saved: <error>`) and nothing changes. Then `EventKind::Hold { reply, hold }` sets `EngineState.brakes.hold`. Idempotent: `on` while on keeps the first `since` and answers `dispatch was already held since <HH:MM> UTC`; `off` while off answers `dispatch is not held`. Messages: on `dispatch held daemon-wide; running sessions continue · anthrex hold off releases it`, off `dispatch released`.
18. **The hold changes no `RunState`** (NA §5 C3): runs stay `Running`, `paused_secs`, `paused_from` and the estimates are untouched. The orchestrator's `resume_run` (9.9) and the user's `run resume` cannot lift it: neither touches `EngineState.brakes`.
19. **What the hold stops.** Decision 11's gate for **every** runtime, and these requests, refused in the driver **before** any decider, scout or session starts, with `HOLD_TEXT = "dispatch is held daemon-wide · anthrex hold off"`: `RunRequest::Start` (a plan file), `StartGoal` (new and `--continue`), `Promote`, `Iterate`, the orchestrator's `start_goal` tool (`chain_goal.rs::start_goal_tool`, `driver/orch.rs:255`), and a queued goal's start (`goal_queue.rs::start_queued_goal` returns `Err(HOLD_TEXT)`). The driver reads the flag with `crate::lock(&self.state).brakes.hold.is_some()` — a lookup, nothing else under the lock. Still allowed: approve, reject, retry (it only requeues), override, cancel, finish, resume, deliver, watch, orchestrator wakes, reads and `edit_plan`.
20. **A queued goal stays queued under the hold** (controller ruling, 2026-10-10: dropping a goal the user asked for is worse than waiting). The drain checks the hold first and, while it is on, leaves every queued goal in place and records nothing as dropped. Turning the hold off (`RunRequest::Hold{on:false}`, and a hold file found absent or off at daemon start) triggers the same drain 9.10 runs on profile confirmation, so held goals start then, in queue order, each still subject to its own profile checks.
21. **Every non-terminal run shows `HOLD_TEXT` as an attention line** while the hold is on (NA §5 C3).

### The context handoff (NA §5 A)

22. **Fill is measured from the session's own transcript tail**, the last `TRANSCRIPT_TAIL_BYTES = 262_144` bytes, read on `spawn_blocking` within the run's `git_timeout_secs` (as `history_lines` does), never under a lock:
    - Claude: the last line with `type == "assistant"` and `isSidechain != true`; `message.usage.input_tokens + cache_read_input_tokens + cache_creation_input_tokens + output_tokens`, and `message.model` (for decision 23). `claude-2.1.278.jsonl` gives **49,028**.
    - Codex: the last `token_count`; `info.last_token_usage.input_tokens + output_tokens` (`cached_input_tokens` is a subset of input), and `info.model_context_window` as the window. `codex-0.155.0.jsonl` gives **23,276 of 258,400** (line 26). **(R)** NA §5's test says 23,193, which is line 22, not the last `token_count`.
    - A first line that is cut by the tail is skipped; a line that does not parse is skipped.
23. **The window** (first that applies) **(R)**: (1) `[orchestrator] context_window_tokens` when > 0; (2) Codex: the rollout's `model_context_window`; (3) Claude: the orchestrator route's `model` ends with `[1m]` → `ONE_M_CONTEXT_WINDOW = 1_000_000`; (4) Claude: a window learned from any headless Claude `result.modelUsage.<model>.contextWindow` (`SessionEvent::ContextWindow`, kept in memory in `driver/quota.rs`, keyed by the model id as written) for the transcript line's `message.model`, matched exactly, then by `proto::models` canonical id (`models.rs:354`); (5) Claude: `DEFAULT_CONTEXT_WINDOW = 200_000`. NA §5 puts the learned window before `[1m]`; a learned 200,000 for the plain model id would then shrink a 1M session's window, so the explicit tag wins.
24. **The threshold (U13).** `handoff_due(tokens, window, percent, cap) = (cap > 0 && tokens >= cap) || (percent > 0 && window.is_some_and(|w| tokens * 100 >= w * percent))`, with `[orchestrator] handoff_at_percent = 80` (0..=100) and `[orchestrator] handoff_at_tokens = 300_000` (0..=10_000_000). **(R)** U13 says "0 disables" for two keys: each 0 disables its own criterion, both 0 disable the handoff. A known token count with no known window still hands off at the cap.
25. **Only at the goal boundary (NA §5 A3).** In `continue_request`, after `joined()` and only when `joined.adopt`, the driver copies out the window's session files (decision 26), measures (decision 22), and when `handoff_due`: sets `adopt = false`, sets `Run.handoff = Some(HandoffRecord { from_run, from_window, fill_tokens, window_tokens, at })`, reads the chain's history lines as a fresh session does, and builds the first prompt with `handoff_prompt`'s new last line `The previous session was <n>% full (<tokens>/<window>); this one starts fresh.` (`<n>%` and `/<window>` are omitted when the window is unknown: `The previous session had <tokens> tokens of context; this one starts fresh.`). In the engine, `chains::join` treats a run with `handoff.is_some()` as `Fresh` even though the chain has not ended: no `adopt`, `prev.orch.orchestrator.live = false`, `chain.window_id = 0`, and `Effect::RenameWindow { window_id: from_window, name }` (decision 27). The run log gets `handed off from <h4>: context <n>% full` (`HANDED_OFF_TEXT`; without a window `… context <tokens> tokens`).
26. **Session files.** `WindowManager::session_files(window_id) -> Option<SessionFiles { runtime, transcript_path: Option<PathBuf>, session_id: Option<String>, started_at: u64 }>` (new `manager/session_files.rs`) copies the root conversation's `transcript_path` and `session_id` out under the manager lock and returns; no I/O. Claude reads `transcript_path`. Codex reads the rollout of `session_id` (the notify payload's `thread-id`) via decision 9; that is how a Codex orchestrator auto-hands off (U13).
27. **The old window is not killed (NA §5 A6).** `Effect::RenameWindow` renames it `<h4>/orchestrator (handed off)` (`HANDED_OFF_NAME`) off every lock (`driver/chain_ops.rs`, as `adopt_window` renames at `:96`); a rename failure is logged and ignored. It leaves the chain and the user closes it.
28. **Unmeasured means adopt as today (NA §5 A4).** No session files, no transcript or rollout, nothing parsed, a timeout, or (with the token criterion off) no window: the run adopts and logs once `context fill unknown; continuing in the same session` (`FILL_UNKNOWN_TEXT`).
29. **Mid-run: an attention line only (NA §5 A5).** Every `FILL_CHECK_EVERY = 60 s` the driver's `on_tick` measures, off-lock, each `Running` run's live orchestrator and sends `EventKind::OrchestratorFill { run_id, fill: Option<Fill> }`; the engine keeps it in `RunOrch.fill` (`#[serde(skip)]`). At ≥ `FILL_ATTENTION_PERCENT = 90` of a known window the run's attention has `orchestrator context <n>% full`. No alert kind is added.
30. **The record (NA §5 A7).** `Run.handoff: Option<HandoffRecord>` (`#[serde(default, skip_serializing_if = "Option::is_none")]`), `RunInfo.handoff: Option<HandoffInfo>`, `RunRecord.handoff: Option<HandoffInfo>` in `history.jsonl`, and the inspector row `handoff   from <h4> · context <n>% full (<tokens>/<window>)`.

## Review focus

1. **The unit trap.** A Claude fraction read as a percent never brakes; a Codex percent read as a fraction always brakes. Check every path into `Permille` (M9.15.2, M9.15.3 `rate_limit_event_yields_per_mille_not_percent`, `codex_limits_maps_by_window_minutes`, the Verification grep).
2. **The deadlock.** Braked means no sessions, hence no readings: a trip must release at `until` on a `Tick` alone (M9.15.4 `brake_releases_at_resets_at_without_a_new_reading`, M9.15.5 `release_on_tick_republishes`).
3. **Finishing in-flight work.** A braked or held run must still review, fix, merge and deliver what it started (M9.15.5 `in_flight_task_keeps_its_reviewer_and_fix_round_while_braked`, M9.15.7 `hold_keeps_run_running_and_open_turns_alive`).
4. **No blocking under a lock.** Rollout, transcript and `brakes.json` I/O run on `spawn_blocking` with deadlines; `forward` never awaits a read (M9.15.6 `codex_rollout_read_times_out_cleanly`, M9.15.8 `transcript_read_times_out_and_adopts`).
5. **Constructed inputs.** The parsers are tested on captured fixtures; a test that edits a line does so in the test, never in the fixture (M9.15.1's pinning test).
6. **The hold fails closed, the quota fails open.** A corrupt `brakes.json` holds; a missing reading never brakes.

## Risks and gotchas

- **The rollout and `rate_limit_event` shapes are undocumented.** A changed shape must yield no reading (unmeasured, fail open), never a wrong number. M9.15.1's captures are the evidence; re-capture when a CLI's major version changes.
- **Codex ephemeral sessions have no rollout.** Deciders and scouts run `codex exec --ephemeral` (`headless/argv.rs:505-506`); they never give a Codex reading. A worker always has one unless the user's runtime command redirects `CODEX_HOME` away from the daemon's environment.
- **Readings exist only while sessions run.** After a daemon restart every runtime is unmeasured until the first turn; that first wave is never braked (decision 8).
- **80 % of a 1M window is 800k tokens**, past where long sessions degrade; U13's 300,000 cap is what fires there.
- **The handoff loses in-session nuance** beyond the summary and the last ten history lines (decision 24 of 9.3).
- **The old window after a handoff is no longer the chain's**; if the user types in it, nothing anthrex does follows. Its name says so.
- **A hold left on by mistake** stops everything quietly: the badge, the alert, the attention line on every run and `anthrex run status` all say so.
- **`HoldInfo` already exists** (a plan approval hold). Every new name in this milestone says `DispatchHold`, `Hold { on }` (a request) or `brakes`; the TUI's `AlertKey::Hold` and `RouteKind::Hold` are the approval hold and are untouched.
- **`app/mod.rs` (599), `cli/src/main.rs` (596), `planners.rs` (589) and `engine/orch.rs` (592)** are at the size limit before this milestone; the move-only splits come first.
