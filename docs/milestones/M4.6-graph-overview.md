## Goal

`C-b T` shows the agents as a drawn tree: rounded boxes joined by lines, roots on the left, children to the right, on a canvas that pans. And the sub-agent boxes say something — `Explore: find every call site` rather than `Explore: Repository: /Users/danielpina/De…`.

## Scope

**In.**

- The Claude sub-agent label reading `description` first.
- A pure left-to-right layout, a painter, a two-dimensional viewport, hit-testing, and the keys.
- `C-b T` rendering the graph instead of aligned rows, and the footer showing the selected node in full.
- Deleting `WideColumns` and `wide_line`, which the overview was the only caller of.

**Out.**

- Any protocol change. `SubagentInfo.label` already exists; this milestone is client-side apart from the label fix, which changes what goes *into* an existing field.
- The sidebar. Its guides, geometry and behaviour are untouched.
- `anthrex tree` on the command line, which has its own formatting.
- Panning keys. The selection reveals itself; the wheel and drag do the rest.
- Sorting, searching or any view that is a table. `anthrex ls` is the table.

## Design decisions

Final. If one proves wrong, stop and record the evidence under "Implementation notes".

1. **The Claude label order is `description`, then `name`, then the first line of `prompt`**, each skipped when absent or empty. `name` stays although Claude Code does not send it: it costs nothing and other spawners may. `LABEL_MAX_CHARS` stays 60. Codex's keys are unchanged.
2. **Left to right.** Tier 0 is projects, on the left. Depth grows rightward, siblings stack downward.
3. **Every node in a tier shares one width**: the widest content in that tier, plus two borders and one space of padding each side, clamped to `MIN_NODE_WIDTH..=MAX_NODE_WIDTH` (12..=30). Tiers differ from each other.
4. **`NODE_HEIGHT` is 3, `TIER_GAP` 3, `ROW_GAP` 1.**
5. **`x` is the sum of the widths of the tiers to the left plus `TIER_GAP` each.** Not `depth × constant` — tier widths differ.
6. **`y` comes from one post-order walk.** A leaf takes the next free row and advances it by `NODE_HEIGHT + ROW_GAP`; a parent centres on the span from its first child's top to its last child's bottom, rounded down.
7. **A node with no *visible* children is a leaf**, whether it has none or is collapsed.
8. **Layout consumes the same visible row list the sidebar builds.** Collapse, the filter and selection therefore keep working with no new code, and the `j`/`k` order is by construction the sidebar's order.
9. **Layout and painting are separate.** `layout(rows) -> Layout` is pure and asserted by rectangles; `paint(&Layout, viewport, &App) -> Vec<Line>` fills a character grid and is asserted by exact strings.
10. **Widths are display widths**, measured with `unicode_width`. A label of wide characters that overflows by one cell breaks every border to its right.
11. **Boxes are rounded**, matching the app's existing `BorderType::Rounded`. Content is one row: status glyph in its status colour, then the tree position for window nodes, then the name or label, truncated with `…`.
12. **The focused window's box uses the focused border style; the selected node is highlighted** the way the selected row is today.
13. **Edges live in the `TIER_GAP` columns.** One visible child is a straight horizontal run. Several children use a vertical bus in the middle gap column, spanning the first child's middle row to the last child's, with a horizontal run into each child. Junction glyphs follow from which arms meet at a cell: `┌` at the bus's top and `└` at its bottom, `├` at a middle child, `┤` at the parent's row when no child sits there, and `┬`, `┴` or `┼` where the parent's row coincides with the top, the bottom or a middle child respectively. Corners are sharp, not rounded — `└` already means "last child" in the sidebar's guides. A border an edge meets becomes `├` on the parent and `┤` on the child.
14. **`Pan { x, y }` is the canvas coordinate at the viewport's top-left**, clamped so the viewport never extends past the canvas.
15. **Reveal is the two-dimensional form of the existing rule**: after any change of selection, rows or focus, if the selected node's rectangle is not wholly inside the viewport, the pan moves by the smallest amount on each axis that puts it inside.
16. **There are no panning keys.** The wheel scrolls vertically by three rows; dragging with the left button pans both axes.
17. **Keys are the existing tree-mode keys**, plus `h` and `l` for parent and first visible child, which had nothing to mean in a list. `h` at a root and `l` at a leaf are no-ops.
18. **The footer shows the selected node in full**: label untruncated, model, state, elapsed. That is where the aligned columns went.
19. **Clicking a node selects it; double-clicking focuses it.** A click on an edge, a gap, or past the canvas does nothing.
20. **`node_at` scans placed nodes linearly.** A click is not a hot path.
21. **`WideColumns` and `wide_line` are deleted** with their tests. `narrow_line` and the sidebar stay.
22. **Decision 27 of milestone 4.5 — that the sidebar and overview share guide strings — no longer applies to the overview**, which draws no guides. The sidebar's guides are unchanged.

## Interfaces

```rust
// crates/tui/src/graph/mod.rs
pub const MIN_NODE_WIDTH: u16 = 12;
pub const MAX_NODE_WIDTH: u16 = 30;
pub const NODE_HEIGHT: u16 = 3;
pub const TIER_GAP: u16 = 3;
pub const ROW_GAP: u16 = 1;

pub struct PlacedNode { pub key: NodeKey, pub rect: Rect, pub depth: u16 }

/// One parent-to-children connection, in canvas coordinates.
pub struct Edge { pub parent: NodeKey, pub children: Vec<NodeKey> }

pub struct Layout { pub nodes: Vec<PlacedNode>, pub edges: Vec<Edge>, pub size: (u16, u16) }

pub fn layout(rows: &[crate::tree::Row<'_>]) -> Layout;
impl Layout {
    pub fn node(&self, key: &NodeKey) -> Option<&PlacedNode>;
}

// crates/tui/src/graph/paint.rs
pub fn paint(layout: &Layout, area: Rect, pan: Pan, app: &App) -> Vec<Line<'static>>;

// crates/tui/src/graph/viewport.rs
#[derive(Debug, Clone, Copy, Default, PartialEq, Eq)]
pub struct Pan { pub x: u16, pub y: u16 }
impl Pan {
    pub fn clamped(self, canvas: (u16, u16), area: Rect) -> Pan;
    pub fn revealing(self, rect: Rect, canvas: (u16, u16), area: Rect) -> Pan;
}

pub struct GraphGeometry { pub area: Rect, pub pan: Pan }
impl GraphGeometry {
    pub fn node_at(&self, layout: &Layout, column: u16, row: u16) -> Option<NodeKey>;
}
```

`App` gains `graph_pan: Pan`. `crates/daemon/src/subagents.rs` changes only the Claude label key tuple and `make_label`'s arity.

## Manual check

With `ANTHREX_SOCKET` and `ANTHREX_DATA_DIR` isolated under `/tmp`, and a real `claude` window that has spawned sub-agents:

1. Press `C-b T`. The tree is drawn with boxes and lines, roots on the left.
2. Sub-agent boxes read like `Explore: find every call site`, not a path.
3. `j`/`k` walk every node in the same order the sidebar uses; the view follows when the selection leaves the screen.
4. `h` and `l` climb and descend; the footer tracks the selection.
5. The wheel scrolls; dragging pans; clicking selects; double-clicking focuses and leaves the overview.
6. Fold a project with `Space`. Its subtree disappears and the layout closes up.
7. Filter with `/`. The drawing rebuilds to just the matches.
8. Resize the terminal narrow and wide. Nothing overlaps and no border is ragged.

## Risks and gotchas

- **Edge junctions are where this will be wrong.** First child, last child, only child, and the parent's row coinciding with the bus are four separate cases and each has a named test. If a diagram looks subtly wrong, suspect these before the layout.
- **Wide characters.** Measure with `unicode_width` everywhere. One cell of overflow breaks every border to the right of it and the cause is not obvious from the screen.
- **Tier width is per tier, not global.** Computing `x` as `depth × constant` passes the simple tests and misplaces every tier after the first whose width differs.
- **The layout must use the visible rows.** Taking children from the model rather than the row list reintroduces the bug milestone 4.5 spent a fix round on, one level up.

## Implementation notes

**Decision 13's junction glyphs were wrong and were corrected mid-milestone.**
The brief originally pinned five glyphs — `┬ ├ └ ┤ ┼` — with a bare `┬` at the
top of a multi-child bus. That cannot be right: `layout` centres a parent on
the span from its first child's top to its last child's bottom (decision 6),
and two distinct boxes of height 3 force that span to be at least 4 rows, so
the parent's own row is always at least two rows inside the bus and can never
coincide with either end. A `┬` at the top would draw a left arm connecting to
nothing in every multi-child tree — which is every interesting tree. The
five-glyph set was missing exactly `┌` and `┴`, the two cells whose left arm
is absent when the parent doesn't arrive there and present when it does. The
task that painted edges (M4.6.4) implemented the brief as written, flagged the
consequence rather than substituting a glyph of its own, and the coordinator
confirmed the decision was wrong and supplied the corrected rule: **the glyph
at each bus cell follows from which of its four possible arms — up, down, a
child's `right`, and the parent's `left` when it arrives there — actually meet
in that cell.** `docs/superpowers/specs/2026-09-20-graph-overview-design.md`'s
decision 13 and `crates/tui/src/graph/paint.rs`'s `bus_glyph` now agree.

**`Pan { x, y }` was defined in `graph/mod.rs` before `graph/viewport.rs`
existed, and moved once it did.** M4.6.3 (the box-and-content painter) needed
`Pan` in `paint`'s signature before M4.6.5 (the viewport) had been built, so
it added `Pan` as data only, documented as provisional, to `graph/mod.rs`.
M4.6.5 moved the struct into the new `graph/viewport.rs` and added its
`clamped`/`revealing` methods there, leaving `graph/mod.rs` with `pub mod
viewport;` and `pub use viewport::Pan;` so every existing `use` of `Pan`
elsewhere in the crate kept resolving unchanged.

**The reveal lives in `tree_input.rs`, in `App::reveal_graph_selection`, not
in the renderer.** Two reasons. First, `app.rs` and everything under
`crates/tui/src/ui/` perform no I/O (`AGENTS.md` hard rule 5) and rendering
takes `&App`; a renderer cannot write `graph_pan`, so revealing there would
mean either making rendering take `&mut App` or keeping a second copy of the
rule. Second, decision 15 makes the reveal edge-triggered — it runs after a
*change* of selection, rows or focus — while decision 16 leaves the wheel and
a drag as the only ways to look away from the selection; a renderer that
re-revealed every frame would snap the viewport back to the selection the
instant a person scrolled it away, undoing exactly what decision 16 grants.
`reveal_graph_selection` runs beside `reveal_tree_anchor`, the
one-dimensional rule it generalises, on the same three edges, and is called
once more from `set_graph_viewport` when the canvas rect itself changes.

**`App::on_scroll` and `App::on_click` moved into a new `crates/tui/src/
mouse.rs`.** Wiring the overview's mouse handling (M4.6.7) needed three new
fields on `App` (`graph_pan`, the canvas rect it reveals against, and the
double-click/drag press bookkeeping) plus `on_drag` and the graph's click and
scroll branches. `app.rs` was 596 lines at the time — four short of the
repository's 600-line rule — so nothing new could land there. `on_scroll`
moved out of `app.rs` and `on_click` out of `tree_input.rs` into `mouse.rs`,
"every mouse gesture the client understands," which is also where the new
double-click recogniser, `scroll_graph`, `click_graph` and `on_drag` belong.
`app.rs` finished the milestone at 561 lines.

**`TreeState::overview` is now unread, and is recorded as a follow-up rather
than removed.** It is the one-dimensional viewport the old aligned-row
overview scrolled with; `set_tree_viewports` and `reveal_tree_anchor` still
maintain it, but nothing reads it once the graph replaced that renderer —
panning goes through `App::graph_pan` instead. Removing the field means
changing `set_tree_viewports`'s signature (it currently takes both the
sidebar's and the overview's row counts), which several existing viewport
tests call directly; M4.6.7 was not the task to edit those tests, so the
field stays and the removal is recorded under a "M4.6 observation" heading in
`docs/superpowers/plans/2026-09-17-anthrex-foundation-followups.md` for the
next milestone that touches tree state.

**`scripts/pty_tree_smoke.py`'s project-tree stage changed which screen text
it waits for, not what it proves.** It used to wait for the canonical
repository's full path inside the overview, which only `wide_line` drew —
one of `WideColumns`'s aligned-row helpers, deleted with the rest of that
renderer (decision 21). The graph's project box carries the project's short
name instead, and the canonical root now lives only in the new footer
(decision 18). The stage still filters the overview to the repository's own
windows, walks up to the project box, and reads the root from the footer, so
it still proves a linked worktree's windows are attributed to the canonical
repository — it just reads a different part of the screen to do it, and now
exercises the footer end to end as a side effect.

**`crates/daemon/src/subagents.rs` was split into a small directory module
(M4.6.8).** It was 754 lines: already 672 on `main` before this milestone,
and grown further by M4.6.1's Claude label change. `AGENTS.md`'s 600-line
rule calls for a split by responsibility, not a cut in half, so it became:

- `subagents/spawn.rs` — parsing a spawn request out of a hook's tool input
  into a `PendingSpawn`, plus `make_label` and the runtime-specific key
  constants. Pure parsing, no state.
- `subagents/tracker.rs` — `SubagentTracker`, the state machine that turns a
  stream of hook events into `SubagentInfo` rows and matches a
  `SubagentStart` against the oldest `PendingSpawn` whose type agrees.
- `subagents/tests.rs` — every existing test, moved unedited; all nineteen
  still pass.
- `subagents.rs` itself is now 22 lines: the module doc, the two `mod`
  declarations, and the `pub use` lines that keep `crate::subagents::*`
  resolving exactly as before for the one external caller
  (`crate::subagents::SubagentTracker` from `agent_state.rs`).

No test was edited to make the split work; `tests.rs`'s own `use` statements
were unchanged from the original test module (they already named
`crate::hooks` and `proto` directly rather than relying on a glob from the
parent), so the move needed no adjustment to compile.

### From the whole-branch review

**The reveal in `replace_windows` is now edge-triggered, for the sidebar as
well as the graph.** `App::replace_windows` called `reveal_tree_anchor` on
every `WindowsChanged`, and the daemon publishes one on every status flip and
every output event — several times a second while agents work. The pan
therefore snapped back to the selection about as fast as a person could
scroll away from it, which contradicts decision 16 and spec §4.4. It now
reveals only when the visible row keys or the repaired selection actually
changed; the third edge, focus, reveals from `App::focus` itself, which is the
only thing that moves it from there. The row keys are compared against the
same `self.rows()` call that already derives `previous_order`, so the guard
costs no extra row build. The sidebar's viewport is revealed by the same
function and so gets the same rule: `ui::tests::
sidebar_scrolls_to_keep_the_focused_window_visible` was updated to assert it,
having previously pinned the snap-back as intended behaviour.

**`TreeState::overview` is no longer revealed, only cleared.** Removing the
field would still change `set_tree_viewports`'s signature, so the field and
that signature stay as the note above records; what went is the
`self.tree.overview.reveal(index)` call, which no reader could observe. Two
assertions on `app.tree.overview.top` went with it.

**`paint` and `overview::view` take the visible rows.** The spec's interface
list gives `paint(&Layout, viewport, &App)`, and `paint` derived the rows
itself; `ui::overview::render` then built that list three times per frame and
`mouse::click_graph` built a second one after `view` had already built its.
Painting runs at least ten times a second in a process meant to run for days,
so `paint` now takes `rows: &[Row<'_>]` and `overview::view_of` takes the same,
with `overview::view` left as the one-argument form for callers with no list
in hand. Inside `paint`, `layout.nodes` zips with `rows` (the layout pushes
one node per row, in row order) and the edges read a rect map built in one
pass, in place of a `Layout::node` scan per row and per edge endpoint.

**A wide grapheme cut by either edge of the viewport shifted a whole row.**
`Grid::index` clips one slot at a time and a wide grapheme occupies two — the
grapheme, then an empty continuation — so a pan onto the second slot kept the
empty string and dropped the grapheme, leaving that `Line` one display column
short. Ratatui left-aligns it, so the box's own border, the junction, the bus
and every tier to its right came out one column off the rows above and below;
the mirror case at the right edge left the line one column long. `merge_runs`
now substitutes a space for a leading empty continuation and for a trailing
two-column grapheme, which is where the fix belongs: `Grid` keeps addressing
one canvas column per slot, and only the conversion to lines has to know that
a pair can be split.
