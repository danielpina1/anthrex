## Goal

Runs get better from their own history, and faster where the spec allows.

`anthrex run stats` shows, beside M8b's recorded medians, what the history has taught: every size class that has reached `adapt.min_samples` merged tasks (default 30) gets **budgets refitted automatically** to 2.5 times its median tool calls and working minutes, and **critical-path weights** from its median working time. New **line thresholds** for S and M, and **routing** changes for a class that escalates too often or never, are **proposed**, each with an id, the evidence and the exact change; `anthrex run stats --apply <id>` applies one after the user confirms it, and `--dismiss <id>` silences it. Everything learned is stored in anthrex's data directory, never in the repository, and is frozen into a run when it starts: a refit never changes a running run.

While a run works, a **rate-limit event** on a runtime halves the number of writers that runtime may hold (never below one), and every `recover_after_mins` without another adds one back, up to `max_writers`. The run inspector shows the time left (`est. left ~40m`) and how far the run is from the best the graph allows (`1.2× the bound`).

A planner can opt a critical-path task into a **race**: two headless workers on different runtimes, in separate worktrees `…/<task>.a` and `…/<task>.b`, each through every gate; the first to pass them all becomes the task branch by a compare-and-swap, and the other is stopped and salvaged. It can opt a TDD task into **pairing**: a headless test writer commits the failing test and stops, and a different headless worker makes it pass in the same worktree. Both are off unless a task asks for them. Codex workers get the same **filtered test output** Claude workers got in M8b. All of it is drawn live in `C-b T`, and every transition is tested with `fake-agent`, recorded history files and an injected clock; no test sleeps to synchronise and none needs a model.

## Design decisions

Numbered and final. If one proves wrong or impossible, stop work on it, record the evidence under "Implementation notes", and continue with the tasks that do not depend on it.

### Structure

1. **Where the code lives.** All daemon code is in `crates/daemon/src/run/`:
   - `refit.rs` (samples, statistics, budgets, weights, proposals, apply and dismiss) and `refit_render.rs` (the `run stats` text);
   - `tuning_io.rs` (reading and writing `tuning.toml`);
   - `estimate.rs` (run estimate and bound ratio);
   - `validate_patterns.rs` (the `race` and `pair` plan rules);
   - `contract_patterns.rs` (the test writer's contract, prompts and message texts);
   - `role_launch_patterns.rs` (the racer and test-writer `HeadlessSpec`s);
   - `model_tuning.rs` (new model structs, re-exported from `run/model.rs`);
   - `engine/concurrency.rs`, `engine/race.rs`, `engine/pair.rs`;
   - `git/race.rs` (the crown op and stale-lock clearing);
   - `driver/tuning.rs` (loading, refitting and saving at `run start` and `run stats`).

   **Pure** (no `std::fs`, `std::process`, `std::thread`, `tokio`, `std::time::SystemTime`): `refit.rs`, `refit_render.rs`, `estimate.rs`, `validate_patterns.rs`, `contract_patterns.rs`, `role_launch_patterns.rs`, `model_tuning.rs`, `engine/concurrency.rs`, `engine/race.rs`, `engine/pair.rs`. **I/O**: `tuning_io.rs`, `git/race.rs`, `driver/tuning.rs`. *(M8a decision 2's discipline.)*
2. **Protocol.** `PROTO_VERSION` becomes one above `main`'s value at the start (header). Every field added to an existing struct is `#[serde(default)]`, and every new enum variant is additive, so a milestone-9 `run.json`, snapshot and `history.jsonl` still deserialize. `proto::AgentRole` gains `Racer` (`"racer"`) and `TestWriter` (`"test_writer"`, from M8a's `rename_all = "snake_case"` on the enum; no per-variant rename). New types live in a new `crates/proto/src/tuning.rs`. `RunRequest::Stats` gains two `#[serde(default)]` fields, and `HistoryStats` gains `tuning`. Every new or changed message gets a MessagePack round-trip test. *(AGENTS.md rule 4.)*
3. **Configuration.** One new table, `[orchestrator.adapt]`, in a new file `crates/config/src/orchestrator_tuning.rs`, read by one call from M8a's `orchestrator::read`, stored in `config::Orchestrator.adapt`. Keys, defaults and ranges are in Interfaces. An invalid value is a `Problem` that keeps the default, in M8a's message format (`orchestrator.adapt.min_samples: must be between 5 and 1000 (using 30)`). `crates/config/src/lib.rs` is not touched. The spec's `adapt.min_samples` is `[orchestrator.adapt] min_samples`.

### History and refit

4. **Samples.** `run::refit` reads M8b's history through `run::history_io::read_history`, which already keeps the last line per `record_id`. A task record belongs to a **class** by `run::refit::class_of`: `hub` when `hub` is true, else `S` or `M` by `final_size`; an `L` record belongs to none. This is the classification M8b's `run::stats::aggregate` uses for its rows; if `aggregate` classifies inline, move its rule into `class_of` without changing its output and call it from both. Two sample sets are drawn per class, each in this order:
   1. **Filter.** *Budget and threshold samples*: `outcome == Merged` (not `MergedWithoutApproval`, whose gates the user overrode), not reverted (no `revert` record names the task or, with `task_id = None`, its run), and `pattern != Some(Race)` (a race's `tool_calls` and working time add two lanes). Threshold samples also need `diff: Some(..)`. *Route samples*: every record with `sessions >= 1`, whatever its outcome, because the tasks that escalated and never merged are the evidence a routing rule needs; the same `pattern` exclusion applies.
   2. **Per-run cap.** Sort by `(at, record_id)`. Keep at most `adapt.per_run_cap` (default 10) records per `run_id`, the newest ones. One pathological run can then never supply more than a third of the default 30 samples.
   3. **Window.** Keep the newest `adapt.window` (default 200), so what was learned follows the repository as it changes.

   A class **qualifies** when its set has at least `adapt.min_samples` (default 30) records. *(Spec §15 "After `adapt.min_samples` tasks … of a size"; review focus 1 and 2.)*
5. **Statistics, in integers.** `lower_median(values)` is the value at index `(n - 1) / 2` of the sorted values (M8b decision 35's "lower middle value"). `percentile(values, p)` is nearest rank: the value at index `ceil(p × n / 100) - 1`. Both return `None` for an empty set. Nothing uses floating point, so the same history always gives the same numbers on every machine. A task's **active seconds** are `phases.preparing + phases.working + phases.proof + phases.check + phases.review + phases.merge` from M8b's `PhaseSecs` (queued and blocked time is excluded, because it measures the scheduler and the user, not the task).
6. **Budgets refit automatically.** For each qualifying class, with `f = adapt.budget_factor_percent` (default 250, range 200–300; spec §15 "2–3x the observed median"):
   - `tool_calls = ceil(lower_median(tool_calls) × f / 100)`, clamped to 10..=2000;
   - `minutes = ceil(lower_median(phases.working) × f / 100 / 60)`, clamped to 5..=1440;
   - `tokens = ceil(lower_median(worker_usage.billable()) × f / 100)` only when `adapt.refit_tokens = true` (default false); otherwise the configured token budget (normally none) is kept. M8a decision 40 keeps token budgets off by default because spec §14 measures up to 30x variance on the same task, and a refit does not remove that variance.

   `TaskRecord.tool_calls` is the task's total over its sessions while a budget counts one session (M8a decision 40), so the refit is conservative for escalated tasks, which is the safe direction.

   The new budget is written to `tuning.toml` (decision 10) only when it differs from the class's current effective budget by at least `adapt.min_change_percent` (default 20) on either axis: `|new − cur| × 100 >= min_change_percent × cur`. It is computed at every `run start` (both kinds) and every `run stats`, by `driver/tuning.rs`. `adapt.refit_budgets = false` turns it off, and then `tuning.toml` budgets are ignored too.

   **Precedence** for a task's budget: the plan's `[task.budget]`, then the refit budget of its class, then `[orchestrator.budget.s]` / `[orchestrator.budget.m]`. A hub task uses the `hub` refit budget when there is one, else M's, as M8a does. The rung-4 ceiling for M and hub tasks (M8a decision 38) becomes, per axis, the larger of `[orchestrator.budget.l]` and twice the effective M budget, so a refit M budget can never sit above the ceiling that is meant to be the next size's. *(Spec §15 "Budgets refit automatically".)*
7. **Critical-path weights from history.** With `adapt.path_weights = true` (default), weights are written to `tuning.toml` whenever at least one class qualifies, from the lower median of **active seconds** over its budget samples, and rewritten only when a weight changes by `min_change_percent`. A class that does not qualify is derived, in this order: `m_secs` = measured M, else measured hub, else `3 × s_secs`; `hub_secs` = measured hub, else `m_secs`; `s_secs` = measured S, else `ceil(m_secs / 3)`. The ratios are M8a decision 41's placeholder weights (S = 1, M = 3, hub = M). Derived classes are listed in `PathWeights.derived`. M8a's `critical_len` then uses `run::estimate::weight(&run.limits, task)`: the class's seconds when the run's `limits.path_weights` is `Some`, else M8a's 1 and 3. *(Spec §13 item 2 "weighted by the history median for its size".)*
8. **Line thresholds are proposed.** The engine enforces no line count: M8a's size rules are about modules, hubs and interface changes (M8a decision 9). Line counts appear only in the size rubric that deciders (M8b's `triage` and `size_check` prompts) and M9's planners read. So a threshold changes those texts, which is why the spec makes it a proposal. For each of S and M whose threshold samples qualify: `lines = added + removed`; the proposed threshold is `percentile(lines, adapt.threshold_percentile)` (default 90) rounded **up** to a multiple of 5 (S) or 10 (M), at least 5 or 10. It is proposed when it differs from the current one (`tuning.toml`'s, else 20 and 100) by at least `min_change_percent`. An M proposal is dropped when it would not exceed the current S threshold. The ids are `thresholds.s` and `thresholds.m`. Hunks (spec §7.1 "1–2 hunks") are not refitted: no prompt or rule uses them. *(Spec §7.1 "refit from history", §15.)*
9. **Routing is proposed.** Only the class defaults that M8a decision 8's policy fills in are proposed; a planner's explicit route always wins, as it does today. Each of S and M has a fixed ladder inside spec §9's table:
   - S: `fast/low`, `fast/medium`, `standard/low` (M8a's default), `standard/medium`;
   - M: `standard/medium` (M8a's default), `standard/high`, `frontier/medium`, `frontier/high`.

   Hub stays `frontier/high` (§9) and is never proposed. Over a class's qualifying **route samples**:
   - **Up** when `escalated × 100 > n × adapt.escalate_above_percent` (default 25), where `escalated` counts `max_rung >= 2`: propose the next step up.
   - **Down** when `escalated == 0` and no route sample is reverted: propose the next step down. Quality comes first (spec §1), so a single escalation or revert holds a class where it is.
   - No step exists → no proposal.

   The ids are `route.s` and `route.m`. *(Spec §15 "Size thresholds and routing are proposed"; §9 routing table.)*
9a. **The user's model lists.** *(Added 2026-09-23 at the user's request: "use codex or claude models configured by effort — for M, codex sol or opus; for scouts, codex terra or luna, or sonnet or haiku". Before this, M8a decision 8's per-size defaults were constants and a role could only name a strength.)*

    One table per task class and per role, each holding an ordered list of **candidates**, and an optional `pick`:

    ```toml
    [orchestrator.routes.m]
    candidates = [
      { runtime = "codex",  model = "sol",           effort = "high"   },
      { runtime = "claude", model = "claude-opus-5", effort = "medium" },
    ]
    pick = "spread"          # "first" (default) | "spread"

    [orchestrator.routes.scout]
    candidates = [
      { runtime = "codex",  model = "terra" },
      { runtime = "codex",  model = "luna"  },
      { runtime = "claude", model = "claude-sonnet-5", effort = "low" },
      { runtime = "claude", model = "claude-haiku-4-5" },
    ]
    ```

    - **Tables.** Task classes `s`, `m`, `hub`; roles `review`, `scout`, `decider`, `planner` (sub-planners) and `orchestrator`. A table that is absent, or whose list is empty after validation, leaves that class or role exactly as the earlier milestones resolve it.
    - **A candidate** is `runtime` (`claude | codex`), `model` (non-empty; it must be in the merged roster, M8a decision 23, so its strength is known), and an optional `effort` (`low | medium | high`). A candidate without `effort` takes the class's or role's own default effort (decision 9's `Tuned.routes`, M8b's `scouts.effort` / `deciders.effort`, M9's `planners.effort` / `agent.effort`). An entry naming a model not in the roster for its runtime is dropped with a `Problem`: `orchestrator.routes.m.candidates[1]: claude/claude-opus-9 is not in the roster (entry skipped)`; a bad runtime or effort likewise (`must be claude or codex`, `must be low, medium or high`). Unknown keys and unknown tables are `unknown key, ignored`.
    - **Worker classes (`s`, `m`, `hub`): which candidate a task gets.** Deterministic, in `run::route_pick` (pure, new), applied at `build_run` and to every task an edit adds:
      1. The task's explicit `route` in the plan wins, as today. A planner route that names only `runtime` picks the first candidate of that runtime, when the list has one.
      2. `pick = "first"`: every task of the class gets the first candidate.
      3. `pick = "spread"`: the class's tasks with no explicit route are grouped into **overlap groups** (connected by M8a decision 11's `owns` intersection, so the rule that two runtimes never share overlapping `owns` still holds by construction), and the groups take the candidates round-robin in plan order of each group's first task. This spreads a run's work over both subscriptions (spec §13 item 8) without the planner doing it task by task. A task added later by an edit joins its overlap group's candidate if it overlaps one, else takes the next candidate in the rotation.
      4. The chosen candidate becomes the task's `route` (runtime, model, the model's roster strength, effort). M8a's validation then runs on it unchanged.
    - **Escalation (rung 2) follows the list.** A fresh rung-2 session takes the **next** candidate after the task's current one, cycling, skipping candidates identical to the current route; with a one-candidate list it falls back to M8a's `escalate`. The rung-2 change must not break the overlap rule: a candidate on the other runtime is skipped while any unfinished task on the first runtime overlaps this task's `owns`.
    - **Reviewers (`review`).** The reviewer is the first candidate that satisfies M8a decision 8's reviewer rule for this task (other runtime than the author, strength at or above the author's, and at least the review level's strength); none qualifying falls back to `pick_reviewer`. The candidate's `effort` wins over the review level's effort when it is set.
    - **Roles (`scout`, `decider`, `planner`, `orchestrator`).** `pick = "first"` uses the first candidate every time. `pick = "spread"` rotates through the list per session in the order sessions start (per run for scouts and sub-planners; per daemon for deciders), which spreads readers over both subscriptions. For deciders a candidate list replaces `deciders.mode`'s runtime choice, but `mode = "off"` still turns deciders off. For the orchestrator only the first candidate is used (there is one orchestrator per run), and it wins over `[orchestrator.agent] runtime/model/effort`.
    - **Precedence**, highest first: the plan's explicit route; the model list; an applied `route.<class>` in `tuning.toml` (decision 11); M8a decision 8's default. A class with a model list gets **no** `route.<class>` proposal (decision 9), and `run stats` shows its route row as `list (config): codex/sol high, claude/claude-opus-5 medium`.
    - **Frozen at start.** `run::refit::tuned` copies the lists into `Tuned.lists`, and `build_run` into `RunLimits.route_lists` (`#[serde(default)]`), so edits, rung-2 sessions and reviewers of a running run use the run's copy; editing the config never changes a running run.
    - **Hub stays hub.** A hub task still runs alone, is `tdd` and is always reviewed; only its model and effort come from the list.
    - **The planner sees the lists.** M9's `get_context` returns them under `limits.routes`, and both planner contracts gain the line `Model lists are set by the user; leave route empty to use them, or name one of the listed models.`
    - With no `[orchestrator.routes.*]` table at all, every output is byte-identical to decisions 9–12 and to M8a, M8b and M9.
10. **The tuning file.** `<repo_dir>/tuning.toml`, next to M8b's `history.jsonl` (`repo_dir` is M8b decision 4's `profile::repo_dir(data_dir, project)`), holds `proto::TuningFile` (Interfaces). Nothing is written into the repository.
    - **Who writes what.** `[budgets.*]` and `[weights]` are written only by the automatic refit; `[thresholds]` and `[routes.*]` only by `--apply`; `[dismissed]` only by `--dismiss`.
    - **Writes** go through M8b's `profile::store::write_atomic` (temp file, `fsync`, rename, directory `fsync`), on `spawn_blocking`, under a per-repository `tokio::sync::Mutex` kept in `RunService` (`TuningLocks`), so a `run start` and a `run stats` in the same repository never interleave a read-modify-write. The lock is never the manager lock and is never held across a git call.
    - **Absent** file: every value is the default. **Unparseable** file: it is renamed to `tuning.toml.bad-<unix secs>`, the run log and `run stats` say `tuning.toml did not parse (<error>); it was moved to <path> and tuning starts again from history`, and the refit starts from an empty file. A broken tuning file must never stop a run, because every value in it has a safe default.
    - A run with an empty `Run.repo_dir` (M8b: history off) reads and writes no tuning at all.
11. **Proposals in `run stats`.** `run::refit::report` returns a `TuningReport` (the effective values per class and the current proposals). `HistoryStats.tuning` carries it, and `run::refit_render::render` prints it after M8b's table (exact text in Interfaces). A proposal whose proposed value equals the `[dismissed]` entry for its id is not listed; a different value is listed again.
    - `anthrex run stats --apply <id>…` first fetches the stats, prints each named proposal and asks `apply <id>: <text>? [y/N]` unless `--yes`, then sends `RunRequest::Stats { apply: [ids] }`. The daemon re-derives the proposals from the same history under the tuning lock and applies only ids still current. An unknown id refuses the whole request: `no current proposal <id>; run anthrex run stats to see the proposals`.
    - `--dismiss <id>…` records `dismissed[id] = <proposed value>` without asking.
    - Applying writes `[thresholds]` or `[routes.<class>]`. It affects runs started afterwards, and M9's planners from the next plan edit of a new run. *(Spec §15 "proposed in `anthrex run stats` and applied when the user confirms".)*
12. **Frozen at start.** `driver/tuning.rs` turns the tuning file and config into a `run::refit::Tuned`, which M8a's `BuildContext` carries in its new `tuning` field (`Tuned::default()` means "nothing learned" and reproduces M8a exactly). `build_run` copies it into the run's `RunLimits`: `budget_s`, `budget_m`, `budget_hub`, `budget_l` (decision 6), `class_routes`, `path_weights`, `thresholds`, and decision 16's concurrency settings. `resolve_task` reads strength and effort by class from `limits.class_routes` instead of M8a decision 8's constants, and the hub budget from `limits.budget_hub`. Plan edits, retries and rung-2 sessions of a running run use `run.limits`, never the file, so **no refit and no applied proposal ever changes a running run**. The run log records what was used, one line each: `tuning: budget S 55 calls 18m from 34 samples`, `tuning: path weights S 550s, M 1650s (derived), hub 1650s (derived)`, `tuning: thresholds S 35, M 100 lines`, `tuning: route S standard/medium (applied)`. With nothing learned, the one line `tuning: none (history has fewer than <min_samples> samples per class)`.
13. **Where thresholds reach.** M8b's `TriageInput` and `SizeCheckInput` gain `#[serde(default)] thresholds: SizeThresholds` (default 20 and 100). `decider::prompt::render` writes the numbers from it where M8b's exact texts say `about 20 changed lines or fewer` and `about 100 changed lines or fewer` (and `more than about 100 lines` in the size-check prompt). With the defaults its output is byte-identical to M8b's. The driver fills triage's from the repository's tuning and the engine fills the size check's from `run.limits.thresholds`. M9's planners see the rubric in two places, and both follow the run's thresholds:
    - **`get_context`** (M9 decision 17) renders `limits.sizes.S` and `limits.sizes.M` from `run.limits.thresholds` (`… about <s_lines> changed lines`, `… about <m_lines> changed lines`). With the defaults its output is byte-identical to M9's example.
    - **`ORCHESTRATOR_CONTRACT` rule 10 and `PLANNER_CONTRACT` rule 4** stay fixed constants (M9 decision 41 keeps them fixed so the cached prefix is stable), and their two numbers are replaced, once, by a pointer to `get_context`. Exact new text of the orchestrator's rule 10: `10. Every task is S or M. S: one file, no interface change, a mechanical check exists, and about as many changed lines as get_context's limits.sizes gives for S. M: one to three files inside one module, a clear spec, a check exists, and about as many changed lines as limits.sizes gives for M. Anything larger is L, and L is never executed: split it.` The planner's rule 4 gets the same two sentences in place of its S and M sentences, and the rest of it is unchanged.
    - Chain collapse is contract guidance for the planners (M9 contract rule 13; M9 decision 23.4 was removed 2026-09-22), with no engine check and no weights, so decision 7's weights do not touch it.

### Estimates

14. **Run estimate and bound ratio**, `run::estimate::estimate(run, now) -> Option<Estimate>`, computed by M8a's `run/snapshot.rs` on every publish into `RunInfo.estimate_left_secs` and `RunInfo.bound_ratio_permille` (M8c's placeholders). `None` when `run.limits.path_weights` is `None`. Over tasks that are not `cancelled`, with `w(t)` the task's class weight and `done(t)` its active seconds so far (decision 5, plus `now − phase_since` when its current state is an active phase):
    - `remaining(t)` = 0 for `merged`, else `max(w(t) − done(t), ceil(w(t) / 10))`, so an unfinished task never counts as free.
    - `left = max(RCP, ceil(Σ remaining / max_writers))`, where `RCP` is the longest path of `remaining` over unfinished tasks along declared and implicit dependencies, the same graph as `critical_len`.
    - `bound = max(CP, ceil(Σ w / max_writers))`, where `CP` is the longest path of `w` over every non-cancelled task. This is spec §13's "wall-clock ≈ max(critical path × …, total work ÷ writers)" with history medians standing in for work, check, review and merge.
    - `elapsed` = `now − approved_at − paused_secs`, less `now − paused_at` while paused or halted (decision 15). `approved_at` is M8c's.
    - `bound_ratio_permille = (elapsed + left) × 1000 / max(bound, 1)`, and `None` before the run is approved.

    M8c already renders both (`est. left ~40m`, `1.2× the bound`); nothing in the view changes. *(Spec §16.4 run mockup; M8c "Consumes from later milestones".)*
15. **Pause accounting.** `Run` gains `paused_at: Option<u64>`, `paused_secs: u64` and `last_step_at: u64`. The reducer sets `last_step_at = now` whenever an event changes a run (the same condition that bumps its revision), sets `paused_at` when a run enters `paused` or `halted`, and adds `now − paused_at` to `paused_secs` when it leaves. On `Restore`, a run M8a turns from `running` into `paused` gets `paused_at = last_step_at`, so the time the daemon was down counts as paused, not as work.

### Adaptive concurrency

16. **Per-runtime writer caps inside a run.** `Run.concurrency: BTreeMap<String, RuntimeConcurrency { cap, last_rate_limit_at, last_change_at, halvings, recoveries }>`, keyed by the runtime label M8a uses for `rate_limits`, with `cap` starting at `max_writers`. With `limits.adaptive_concurrency` (config `adapt.adaptive_concurrency`, default true, frozen at start):
    - **The event.** A rate-limit event is exactly what increments M8a's `Run.rate_limits[runtime]` (M8a decision 32): the start of an `ApiRetry` streak with a rate-limit error, or a turn that ends `Failed { kind: RateLimit }`, except when that failed turn arrives inside a streak, which is the same event. So M8a's `e2e_rate_limit_retry_is_not_a_stall_and_a_failed_turn_is_continued` keeps `rate_limits["claude"] == 1`, and a failed turn with no streak before it halves writers too. M9.5 adds no counting of its own; `on_rate_limit` is called wherever M8a increments the counter. Every run session counts, readers included, because they share the runtime's subscription window (§13 item 8, §23).
    - **Halving.** On an event, `last_rate_limit_at = now`. If `now − last_change_at >= limits.halve_hold_secs` (config `adapt.halve_hold_secs`, default 60), or the cap has never changed: `cap = max(1, cap / 2)` (integer division), `last_change_at = now`, `halvings += 1`. Otherwise nothing more happens. Several sessions hitting one exhausted window in the same minute are one signal, and halve once.
    - **Recovery.** On `Tick`, for each runtime with `cap < max_writers`, if `now − max(last_rate_limit_at, last_change_at) >= recover_after_secs` (config `adapt.recover_after_mins`, default 10, frozen as seconds): `cap += 1`, `last_change_at = now`, `recoveries += 1`. One step per interval, never above `max_writers`. A `Tick` that changes no cap changes nothing, so M8a's `revision_bumps_on_every_change_and_only_then` still holds.
    - **Scheduling.** M8a decision 41's writer-slot check becomes: a task can take a writer slot when `writers_busy < max_writers` **and** the writers busy on its route's runtime are fewer than that runtime's cap. A task blocked only by its runtime's cap is skipped, so a Codex task behind a capped Claude task still starts. Hub-alone is unchanged.
    - **No preemption.** A cap below the writers already running stops nothing; it only holds new dispatches until enough of them finish.
    - **Visibility.** Each change adds a run log line (`rate limit on codex: writers 3 → 1`, `no rate limit on codex for 10 min: writers 1 → 2`). While a cap is below `max_writers`, `attention` carries `codex writers capped at 1 of 3 after a rate limit`. `RunInfo.writer_caps` exposes the caps, and the run report gets a `## Concurrency` section.
    - `adaptive_concurrency = false` keeps every cap at `max_writers`, which is exactly M8a.

    *(Spec §13 item 9, "[J, additive-increase / multiplicative-decrease]".)*

### The race

17. **Opt-in, and what is validated.** `PlanTask` gains `#[serde(default)] race: bool`, and `PlanEdit::AmendTask` gains `#[serde(default)] race: Option<bool>`. Default off (spec §13). `run::validate_patterns::validate` adds, each with the exact text:
    - `task <id>: race: only code tasks can race (rule 4.1.race)`;
    - `task <id>: race: the roster has no <peer runtime> model at strength <strength> for the second racer (rule 4.1.race)` — the second racer is `roster::first_at(roster, peer(route.runtime), route.strength)`;
    - `task <id>: pair: a task cannot both race and pair (rule 4.1)`;
    - amending `race` or `pair` on a task that is not `pending` or `queued`: `task <id>: race: can be changed only before the task starts (it is <state>)` (or `pair:`).

    Racing never overlaps another task's `owns` in a way M8a allows: the two racers work on the same task, and M8a's cross-runtime `owns` rule is about two tasks.
18. **Dispatch.** A task with `spec.race` races only when, at the moment the scheduler would dispatch it:
    - it is `on_critical_path` (spec §4.1 "opt-in for critical-path tasks"), else it runs as a single worker with the note `race skipped: not on the critical path at dispatch`;
    - `max_writers >= 2`, else the note `race skipped: max_writers is 1`.

    It needs **two** writer slots: one on its runtime and one on the peer runtime, each within decision 16's caps. When it is the first runnable task in dispatch order and only one slot is free, **nothing after it dispatches** in that step: it holds the head of the line, because it is the critical path. `Task.race_wait_since` records when it first waited. After `limits.race_slot_wait_secs` (config `adapt.race_slot_wait_secs`, default 120) it gives up racing and starts as a single worker with the note `race skipped: no second writer slot within <n> s`. A race task is never pre-warmed (M8a decision 14): its worktrees are the lanes' own.
19. **Lanes.** A race is `Task.race = Some(Race { lanes: [a, b], winner: None, adopted: false })`.
    - **Lane a** runs on the task's route. **Lane b** runs on the peer runtime at the same strength (decision 17's roster entry) and the same effort.
    - Each lane has its own branch `anthrex/<run>/<task>.a` / `.b` created from the run head, its own worktree `<wt>/runs/<run>/<task>.a` / `.b` (spec §11.6), prepared by M8a's `PrepareWorktree` with `setup`, locked and watched like a task worktree.
    - The task branch `anthrex/<run>/<task>` does not exist until a lane wins.
    - Lane proof and review worktrees are `<task>.<lane>.proof` and `<task>.<lane>.review`. M8a decision 16 keeps `.` out of task ids, so none of these can collide.
    - Each lane's racer is a headless session with role `AgentRole::Racer`, the next task session number, and `lane` set on its `AgentRound`, `RunRef` and `McpTarget`. Its window is named `<h4>/<task>.<lane>w<session>`, its reviewers' `<h4>/<task>.<lane>r<round>`.
    - A racer gets exactly a worker's contract, allowed tools, sandbox and prompt (`WORKER_CONTRACT`, `worker_prompt` with its lane's worktree and branch). It is not told it is racing, so it has no reason to rush, and the cached prompt prefix stays the worker's.
    - Both lanes' session spend adds to the task's `spent_total`. Racing doubles the tokens of the raced task, as spec §13 says.
20. **Lane gates and the ladder.** Each lane goes through M8a's gates on its own (done, test proof, check, review), with its own `failures`, `bounces`, `stalls` and `budget_exceeded`, and its own reviewer (`pick_reviewer` on the lane's route, so lane a is reviewed by Codex and lane b by Claude on the default roster). Every op and record of a lane carries `lane: Some(..)` (`PendingOp`, `CheckRecord`, `ProofRecord`, `ReviewRecord`), and an `OpDone` is routed to its lane.
    - A lane's **first gate failure** is rung 1: the failure text goes to that lane's session as its next turn.
    - Anything that would take a single worker **past rung 1** takes the lane out of the race: a second gate failure, a stall, a hard budget breach, a spill outside `owns`, `task_blocked` of any kind (a race cannot wait for an answer), or an environment block.
      - While the **other lane is live**, the lane is **eliminated**: `LaneState::Out` with the reason; its sessions are stopped and its worktrees salvaged (decision 22).
      - When the **other lane is already out**, the lane is **adopted** instead (decision 21's crown with `adopt: true`), and M8a's ladder then applies to the task the action that took it out, with the task's counters set from the adopted lane: a second failure is rung 2 (a fresh session in the adopted worktree on `roster::escalate`), a question is `blocked(question)` answered as usual, a spill is rung 3.
      - Racing already put a second runtime on the task, which is what rung 2's peer runtime would have done.
21. **Winning.** "The first racer to pass every gate wins" (§11.6): a lane **passes** when its last gate succeeds — its review approves (or has only minor findings), or its check passes when the task is not reviewed (M8a decision 35, `review_small = false`).
    - **One winner.** The reducer handles events one at a time, so exactly one lane passes first. That lane becomes `Won`, and the reducer emits `Op CrownRacer { adopt: false }`. From then on, anything the other lane does — a passed gate, a verdict, a `task_done` — is recorded and never crowns: its state is `Lost`, and a tool call gets `the race for task <id> is over: racer <lane> won. Stop now.`
    - **The crown op** (`run/git/race.rs::crown`):
      1. `git update-ref refs/heads/anthrex/<run>/<task> <lane head> <zero oid>`, a compare-and-swap that creates the task branch only if it does not exist yet. The zero oid is `0` repeated for the length of the repository's object format (`git rev-parse --show-object-format`: 40 for sha1, 64 for sha256).
      2. `git checkout anthrex/<run>/<task>` in the winning lane's worktree, which switches branch without touching a file because both refs name the same commit.
      3. The result is `Crowned { head }`. If the task branch exists at another commit, the result is `RefMoved` and the run halts, as for a moved run ref: a ref only the engine writes (M8a decision 21; only the base branch may move without a halt).
    - **Idempotence.** An existing task branch at the lane head counts as done.
    - **Then** `Task.worktree` becomes the lane's worktree, and the task goes straight to the merge queue with the winner's head — "the winner then enters the merge queue like any task" (§11.6).
22. **Stopping and salvaging the loser.** Spec §11.6: "stops the other racer, salvages its worktree to `refs/anthrex/salvage/…`, and removes it". The same happens to an eliminated lane (decision 20).
    - **Stop.** `KillWindow` for the lane's live racer and reviewer. Its lane proof and review worktrees are removed as M8a removes them.
    - **Wait before removing.** The lane worktree's `RemoveWorktree` is emitted only when every pending op on that lane has returned and the racer's `ProcessExited { killed_by_engine: true }` has arrived (or its session had already ended). A check or proof must never run in a worktree being removed.
    - **What the removal does.** `RemoveWorktree` gains `keep_head: bool` and `kill_group: Option<u32>`:
      - `kill_group` is the racer's process group. The driver sends it `SIGKILL`, ignoring `ESRCH`, and waits until `killpg(pgid, 0)` fails, at most `STALE_GROUP_WAIT` (5 s). M8a's kill sends `SIGTERM` and `SIGKILL` only after `INTERRUPT_GRACE`, so a `git commit` child can still be alive when the session's main process has exited.
      - With the group gone, `run::git::clear_stale_locks(worktree, lane_branch)` removes `index.lock` and `HEAD.lock` in the worktree's own git directory, and `<git common dir>/refs/heads/<lane branch>.lock`. No process can still own them. Each removal is recorded as `removed a stale <file> left by the stopped racer`.
      - Then M8a's salvage runs. With `keep_head: true`, a **clean** worktree also gets its salvage ref, pointing at `HEAD`. Without it the loser's commits would live only on `anthrex/<run>/<task>.<lane>`, which `run accept` deletes with every run branch (M8a decision 20). The ref is `refs/anthrex/salvage/<run>/<task>/<seq>` with the task's own `<seq>` counter (M8a decision 20). It is recorded as the lane's `salvage_ref` and in the report.
    - **The lane's branch** is kept until accept or discard, like every run branch.
23. **After the race.** A crowned or adopted task is an ordinary M8a task: hand-back on conflict (M8a decision 36) merges the run head into `Task.worktree` and resumes the winning lane's session, and rung 1 after a red candidate goes to that session. `run::model::Task::current_writer()` (new) is the last round whose role is `Worker` or `TestWriter`, or `Racer` with its lane `Won` or `Adopted`. Every M8a rule that meant "the task's worker" uses it: tool authorisation, delivery, stall, budget, fresh sessions. Cleanup on merge removes `Task.worktree`, not `run.task_path(task)`. Other operations:
    - **Cancel** kills both lanes and salvages both.
    - **An `amend_task` brief or `answer`** goes to every live lane.
    - **Pause** lets open turns end.
    - **Restart** resumes each live lane round by M8a decision 45, because lanes are rounds.
    - **`run retry`, `run override`** apply only after adoption, when the task can be `blocked`. A racing task is never `blocked`.

    A racing task's `TaskState` is `Working` from dispatch until its crown, whatever its lanes are doing. Each live lane holds a writer slot from `Preparing` through `Check`, as M8a's writers do.

### The test writer, then the implementer

24. **Opt-in, and what is validated.** `PlanTask` gains `#[serde(default)] pair: bool`, and `AmendTask` gains `pair: Option<bool>`. Spec §4.1 names hub tasks as the use and makes pairing opt-in per task. Validation therefore allows `pair` on any code task that resolves to `tdd`, and M9's orchestrator contract recommends it for hub tasks (decision 32). There is no default, for hub tasks or any other. Rules, exact:
    - `task <id>: pair: a paired task needs test mode tdd (rule 4.1.pair)`, checked after M8a decision 10's resolution, so a `tdd` task demoted to `check` by a missing `single_test` fails here;
    - `task <id>: pair: name the test the test writer writes in test_to_write (rule 4.1.pair)`.
25. **The test writer.** At dispatch, a paired task gets `Task.pair = Some(Pair { phase: Writing, .. })` and, in its normal task worktree, a headless session with role `AgentRole::TestWriter`, window `<h4>/<task>.t<session>`.
    - **Route.** The peer runtime at the same strength and effort when the roster has one (`roster::first_at`), else the task's route. A test and its implementation from two different models make it less likely that the test only encodes the implementation's own assumptions. [J]
    - **Contract and prompt.** Contract `TEST_WRITER_CONTRACT`, first turn `test_writer_prompt` (both exact in Interfaces). Tools, sandbox and budget are a worker's (the class budget, per session).
    - **Its `task_done`** goes through M8a's `VerifyDone` exactly as a worker's does: commits, a clean tree, `owns`, generated and protected files, and `test` and `red` required. In addition, `red` must be the branch head (`red_ok` from `VerifyDone`, plus `red == head`). Otherwise: `task_done rejected: you are the test writer, so red must be your last commit (HEAD is <head7>, red is <red7>). Commit only the failing test, then call task_done again.`
    - **The red check.** An accepted claim emits `Op RedCheck`: M8a's proof worktree, `git checkout --detach --force <red>`, `git clean -fd`, and `single_test` with `{test}` shell-quoted. It must exit non-zero.
      - It passes (exit 0): a gate failure of gate `proof` on M8a's ladder, with `red_check_failed_message`. Rung 1 returns it to the same test writer, rung 2 starts a fresh test writer, rung 3 raises the size.
      - It fails, as it should: `pair.test` and `pair.red` are recorded, `red_checked = Some(true)`. The test writer's session is retired (M8a decision 52), and the run log gets `pair t2: red a1b2c3d fails as it should; implementer started`.
26. **The implementer.** In the same worktree, one after the other (§4.1): a headless session with role `Worker`, the next session number, the task's own route. Its prompt is `worker_prompt` with `pair_implementer_note` placed before the brief. Before it starts, the test writer's counters are moved to `pair.writer_failures` and the task's `failures`, `bounces`, `stalls` and `budget_exceeded` are reset to 0: the implementer's ladder starts fresh, because the test writer's failures were about a different job.
    - **Its `task_done`.** `test` and `red` are optional; when absent they are filled from `pair`. When given, they must equal `pair`'s: `task_done rejected: this task's test was written by the test writer; name test <test> and red <red7>, or leave both out`.
    - **Its gates** are M8a's in full: the proof (red fails, head passes and matches `test_passed`), check, review and merge.
    - **The reviewer prompt** of a paired task adds `pair_reviewer_note`, which points the reviewer at any change since `red` to the files the red commit touched. That is where a weakened test would be (spec §8.1).
    - **Retry and restart.** `run retry` on a paired task blocked in `Writing` starts a fresh test writer; in `Implementing`, a fresh implementer. Rung 2 in either phase starts a fresh session of that phase's role. Restart resumes whichever session is live (M8a decision 45).
    - **Slots.** The task holds one writer slot throughout; two writers never share the worktree.
27. **Reconcile.** `CrownRacer` checks the task branch and the lane worktree's branch. `RedCheck` is `NotStarted` (it has no side effect). `RemoveWorktree` keeps M8a's row, and a `keep_head` salvage ref present with the path gone replays `Removed`. Interfaces has the table rows.

### The output filter for Codex workers

28. **Codex gets M8b's filter.** M8b's `worker_spec` sets `HeadlessSpec.output_filter` for Claude workers only, because M8a passes Codex no hook configuration. M9.5 sets it for Codex worker-like sessions too (workers, racers, test writers), under the same conditions (stored profile, filter mode not `none`, at least one prefix). It adds `log_dir` to `codex_writable_roots`, so `filter-run` can write its log inside Codex's sandbox. M9.5.1 decides how the filter reaches Codex (`CLI_CAPS.codex_filter`):
    - **`CodexFilter::Hook`**: M9.5.1 finds that `codex exec` and `codex exec resume` run a `PreToolUse` hook given with `-c` and trusted through `hooks.state`, and that the hook can replace a shell call's command. `headless::argv::codex_args` then adds `-c hooks.PreToolUse=[{hooks=[{type="command",command=<filter-hook command>}]}]` and `-c hooks.state={"<trust_key(default_hook_source(), "pre_tool_use", 0, 0)>"={trusted_hash="<trust_hash("pre_tool_use", command)>"}}`, using M3's functions unchanged. It never adds `--dangerously-bypass-hook-trust`, which would also let a repository's own project hooks run (M8a decision 53). `anthrex filter-hook` gains `--runtime codex`, which reads the tool name and command from the payload paths M9.5.1 records (`CLI_CAPS.codex_shell_tool_names`, `CLI_CAPS.codex_command_pointer`) and prints the replacement in the shape M9.5.1 records (`output_filter::codex_rewrite`).
    - **`CodexFilter::Instruction`**: when any of those facts is missing, the filter cannot be enforced. `developer_instructions` then gets `codex_filter_note` (exact in Interfaces) appended after the contract, which tells the worker how to run test commands through `anthrex filter-run`. The run report says `codex output filter: by instruction only (the CLI cannot rewrite commands)`.

    A filter hook sends nothing to the daemon, so M8a decision 25's reason for passing Codex no hooks (no double-counting) still holds.

```
tuning: <repo_dir>/tuning.toml  (refit after 30 samples per class)
  CLASS  SAMPLES  BUDGET          WEIGHT  REFIT
  S      34       55 calls 18m    9m      2026-09-22 14:03
  M      12/30    150 calls 60m   27m*    not yet
  hub    3/30     150 calls 60m   27m*    not yet
  * derived from another class's median

  thresholds.s  S line threshold 20 → 35 (p90 of 34 merged S tasks)
  route.s       S route standard/low → standard/medium (14 of 34 S tasks, 41%, reached rung 2 or higher)
apply with anthrex run stats --apply <id>; dismiss with anthrex run stats --dismiss <id>
```

Rules:
- **Rows.** Each row is `format!("  {:<5}  {:<7}  {:<14}  {:<6}  {}", class, samples, budget, weight, refit)`.
- **`samples`.** `<n>` when the class qualifies, else `<n>/<min_samples>`.
- **`budget`.** `<calls> calls <minutes>m`, then ` <tokens> tok` when a token budget is set, with tokens in M8b's `k`/`M` notation.
- **`weight`.** `<secs / 60>m`, or `<secs>s` under a minute, with a trailing `*` when derived, or `-` without weights. The `* derived …` line appears only when a weight is derived.
- **`refit`.** `yyyy-mm-dd hh:mm` UTC (M8a's report time format), `not yet`, `kept` (qualifies, but within `min_change_percent` of the current budget), or `off`. With `refit_budgets = false`, the header's parenthesis reads `(budget refit off: [orchestrator.adapt] refit_budgets = false)`.
- **Proposals.** Each line is `format!("  {:<12}  {}", id, text)`. With none: `proposals: none`, and no `apply with` line.
- **Threshold text.** `<C> line threshold <cur> → <new> (p<pct> of <n> merged <C> tasks)`.
- **Route text, up.** `<C> route <s>/<e> → <s>/<e> (<k> of <n> <C> tasks, <p>%, reached rung 2 or higher)`, where `p = k × 100 / n`, rounded down.
- **Route text, down.** `<C> route <s>/<e> → <s>/<e> (none of <n> <C> tasks reached rung 2 or higher, none reverted)`.
- **A moved bad file** adds the first line `tuning: tuning.toml did not parse (<error>); it was moved to <path> and tuning starts again from history`.

`--apply` asks `apply <id>: <text>? [y/N]` per id unless `--yes`, then prints `applied <id>: new runs in <project> use it` per id before the stats. `--dismiss` prints `dismissed <id>: it is not proposed again while it would propose <value>`. A refusal prints the daemon's message and exits 1. `--json` prints `HistoryStats` with `tuning`.

## Review focus

The five input classes or failure modes most likely to bite a user that the task tests would not exercise without being told to. Each has a test in its owning task; the reviewer checks those tests exist and fail without the change they guard.

1. **History with too few samples.** A new repository has five runs of history, and a refit from them would set budgets from noise. Nothing may be refitted, weighted or proposed below `min_samples`, and `run stats` must say how many samples each class still needs. Test: `too_few_samples_refit_nothing_and_say_so` (M9.5.4).
2. **An outlier run.** One run with a stuck toolchain produces 25 tasks at 900 tool calls each. Without a per-run cap it would move the S budget from 55 to 88 in one go. Test: `one_outlier_run_cannot_move_a_budget_past_its_cap` (M9.5.4), which asserts both numbers.
3. **Both racers pass at once.** Two approvals in consecutive events, or one while the other's crown op is in flight. A second crown would point the task branch twice and merge the wrong work. Test: `both_racers_passing_in_one_step_crowns_exactly_one` (M9.5.12), with its pending-crown and `RefMoved` variants, and `e2e_race_both_pass_crowns_one` (M9.5.17).
4. **A race loser stopped mid-commit.** Killing a racer while its `git commit` runs leaves `index.lock` and a ref lock. Salvage then fails forever on a lock no process owns, or worse, the worktree is removed without its work. Tests: `a_loser_killed_mid_commit_is_salvaged_after_its_lock_is_cleared` (M9.5.10), and `the_loser_is_stopped_then_salvaged_after_its_ops_and_process_end` (M9.5.12) for the ordering.
5. **Rate-limit flapping.** Several sessions report the same exhausted window within seconds, then it recovers, then it hits again. Naive halving drops to 1 at once and oscillates; naive recovery climbs past the cap. Test: `flapping_rate_limits_halve_once_per_hold_and_recover_one_step_at_a_time` (M9.5.8).

## Risks and gotchas

1. **A refit is only as good as `phases`.** Working minutes come from M8b's `set_state` phase accounting. A daemon that was down while a task was `working` adds the downtime to that task's working phase (M8b decision 31 has no pause notion). One such task is absorbed by the median, but a repository that restarts the daemon mid-run every time will see its minute budgets drift up. The per-run cap limits the damage.
2. **Budgets per session against totals per task.** A refit from task totals is generous for tasks that escalated. That is deliberate: a budget that is too tight sends correct work up the ladder, and one that is too loose only delays a wrap-up message.
3. **Thresholds change prompts, not rules.** Applying `thresholds.s` changes what deciders and planners are told an S task is. Nothing in the engine enforces a line count, so a planner can still write a 300-line S task. The size cross-check and review catch it, as before.
4. **The head of the line is held by a race.** A race waiting for its second slot holds back every task behind it for up to `race_slot_wait_secs`. That is the price of putting the critical path first, and it is bounded. Watch for it with a small `max_writers` and a runtime capped by a rate limit.
5. **Racing doubles the tokens of the raced task** (§13), and both lanes' spend shows in the task's `spent_total`. The rung-4 ceiling counts cumulative spend, so a race that goes long reaches `blocked(human)` sooner than a single worker would. That is the right signal.
6. **The loser's commits survive only through the salvage ref.** `run accept` deletes every `anthrex/<run>/*` branch, lane branches included. Decision 22's `keep_head` is what keeps a clean loser's work reachable; do not "optimise" it away.
7. **Stale locks.** Only locks in the loser's own worktree git directory and its own branch's ref lock are removed, and only after its process group is gone. Never clear `index.lock` in a worktree whose session might still run: a live `git commit` would then corrupt its index.
8. **Codex hook trust.** The filter hook is trusted by hash, which changes when the command string changes: a different `anthrex` path, mode, log directory or prefix list. `codex_hook_args` computes the hash from the exact command it passes. Never pass `--dangerously-bypass-hook-trust`: it would also run a repository's project hooks (M8a decision 53).
9. **Adaptive caps are per run.** Two runs in one repository on one subscription each halve and recover on their own signals, so together they can still exceed the window. That is recorded as a follow-up; the spec's AIMD is per run.
10. **`AgentRole` serialisation.** Under `rename_all = "lowercase"` `TestWriter` would become `testwriter`, which `fake-agent`, `anthrex mcp --role` and the run view would then disagree about. M8a declares the enum `snake_case`, and `agent_roles_serialize_as_words` guards it.
11. **Rows past the ninth.** A raced or paired task adds one or two inspector rows, and the tall panel has nine. `history` drops off first, by M8c decision 29. Do not raise `RUN_INSPECTOR_HEIGHT` for it: M8c's panel-height tests fix it at 12.
12. **Socket and temp paths.** Every new test directory is under `/tmp` (`tempfile::Builder::new().prefix("ax-…").tempdir_in("/tmp")`), never `std::env::temp_dir()`.
