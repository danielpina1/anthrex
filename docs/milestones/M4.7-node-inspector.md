## Goal

Select a node in the graph overview — with the keys or by clicking it — and a panel below the canvas says everything anthrex knows about it: what it is, what model it runs, who spawned it, which checkout it stands in and what that checkout's git state is, and how long it has been doing what it is doing.

## Scope

**In.** The inspector panel, its field sets for projects, windows and sub-agents, its column packing, the `i` toggle, and the collapse to one line on a short terminal.

**Out.**

- Any protocol change. Everything shown is already on the wire.
- A sub-agent's output. A Claude sub-agent runs inside its parent session as a tool call, with no terminal and no input channel; reading the session transcript is its own milestone, and genuine interaction needs anthrex to have spawned the agent, which is milestone 8.
- The sidebar, `anthrex tree`, the canvas, the layout algorithm and the painter. Untouched.
- Editing anything. The inspector is display-only and never takes focus.

## Design decisions

Final. If one proves wrong, stop and record the evidence under "Implementation notes".

1. **The inspector replaces milestone 4.6's one-line footer**, as a rounded box pinned to the bottom of the overview's interior, spanning its full width.
2. **`INSPECTOR_HEIGHT` is 8** — border, title row, five field rows, border.
3. **The title is the node's status glyph in its status colour, then its name in bold.**
4. **Fields flow into columns**: each column is as wide as its widest label plus its widest value plus a two-space gutter; columns pack left to right until the width runs out, then wrap to the next row.
5. **A value too long for its column is elided with `…`**, except the sub-agent's `task`, which wraps across the remaining rows. The box exists so that the label nobody could read in a box can be read here.
6. **Below `INSPECTOR_HEIGHT + 6` rows of interior, the inspector collapses** to milestone 4.6's single line. A short terminal loses the panel, never the canvas.
7. **`i` toggles the inspector** while the overview is open, and the choice is remembered for the session. Off means the single line.
8. **A project's fields** are path (`~`-shortened), status, agents (the tree's runtime counts), and — only when every window in the project shares one worktree — branch and changes. With more than one, branch reads `N worktrees` and changes is omitted, because picking one arbitrarily would be a lie.
9. **A window's fields**, in this order, are status with its tool when one is running, `for` (time in status), model (`-` when none), branch with dirty and ahead/behind, sub-agents as `N, M running`, runtime, dir, worktree (only when it differs from dir), and session (when the runtime reports one). The order is the drop order: a narrow panel keeps what a window is *doing* and loses where it is doing it.
10. **A sub-agent's fields**, in this order, are spawned by, state with its tool, `for` (elapsed while running, otherwise how long it ran), model, kind, and depth, plus task (its label in full) as the wrapping field. `spawned by` leads because §3 calls it the one thing the tree cannot tell you.
11. **"Spawned by" resolves `parent_id`** to that sub-agent's label; when `parent_id` is absent, or names a sub-agent no longer in the list, it is the owning window's number and name.
12. **Git fields come from `App.git`, keyed by the window's `worktree`** — a sub-agent uses its owning window's. Absent state means the fields are omitted, not shown empty.
13. **The inspector is a pure projection.** `fields(row, app) -> Inspection` computes labels and values with no rendering; the renderer lays `Inspection` out. Both are tested separately, the first by exact field lists, the second by exact strings.
14. **Widths are display widths** via `unicode_width`.

## Interfaces

```rust
// crates/tui/src/inspector.rs
pub const INSPECTOR_HEIGHT: u16 = 8;
pub const MIN_INTERIOR_FOR_PANEL: u16 = INSPECTOR_HEIGHT + 6;

pub struct Field { pub label: &'static str, pub value: String, pub wrap: bool }
pub struct Inspection { pub glyph: Span<'static>, pub name: String, pub fields: Vec<Field> }

pub fn inspect(row: &crate::tree::Row<'_>, app: &App) -> Inspection;
pub fn render(frame: &mut Frame, inspection: &Inspection, area: Rect);
```

`App` gains `inspector_visible: bool`, defaulting true. `ui::overview::areas` returns the canvas and the inspector's rect.

## Risks and gotchas

- **Column packing has four cases** — fits, wraps, elides, wraps-and-elides — and each needs its own exact-string test. This is where it will be wrong.
- **The panel eats canvas height**, the axis the tree grows along. The collapse rule is what stops that being a problem on a short terminal.
- **`GitState` is keyed by worktree root, not project root.** A project spanning worktrees has no single branch, which is why decision 8 degrades to a count.

## Implementation notes

### Decisions 9 and 10: the field orders changed (M4.7.1/.2 review)

Both decisions originally listed a window's fields as runtime, model, status,
`for`, dir, worktree, branch, session, sub-agents, and a sub-agent's as kind,
task, model, state, `for`, spawned by, depth. The panel drops fields from the
end when they do not fit (decision 2), and those orders put the best fields
last: below about 35 columns a sub-agent kept kind, model, state and `for`, and
lost `spawned by` and `depth` — the two this milestone exists for, and the ones
§3 says outright the tree cannot give you. A window lost its branch and its
sub-agent counts before its runtime and its working directory.

The field *sets* are unchanged; only their order is. Decisions 9 and 10 above
now carry the new orders, and the drop order is stated as part of them so it
cannot drift again.

### Decision 3: a sub-agent's title is its label alone

The title was `tree::subagent_label`'s `kind: label`, which is right for a
sidebar row and wrong here: the panel has a `kind` field of its own, so the
title repeated a word the fields already carried. It is now the label, falling
back to the kind when there is none. Decision 11's `spawned by` follows the same
reading, for the same reason and because it shortens a value that is otherwise
long enough to cost the panel a column.

### Decision 5: the `task` field is dropped when the title showed it whole

A sub-agent's title is its label and its `task` field is the same label. On a
panel wide enough for the title, the field printed the same words a row below
*and* cost the column flow the row held back for it. It is now emitted by the
projection always and dropped by the renderer when the title did not have to cut
the name short — the condition is width-dependent, and decision 13 keeps the
projection blind to width, so the test belongs in the renderer where the
truncation is already computed.

### Decision 8: a project must be *entirely* on one worktree

The first implementation collected the worktree roots of a project's windows and
showed the branch whenever exactly one came back — which dropped windows with no
worktree before counting. A project with one worktree'd agent beside a plain
shell showed that worktree's branch as the whole project's. `branch` and
`changes` now need every window in the project to be on a worktree, and all on
the same one. More than one distinct worktree still reads `N worktrees`, which
is true whether or not every window is on one.

### Decision 4: how a column is sized, and how many are opened

Two readings the decision does not fix, both settled by what the rendered panels
looked like:

- A column is `label + 2 + value + 2`. The decision's "two-space gutter" is the
  space between columns; §2's `model  opus` is the space between a label and its
  value. Both numbers come from the source texts, only their sum is new.
- Columns are opened while the width takes them, but never more than it takes to
  show every field. Past that a column buys nothing and costs the others their
  room: a window at 76 columns elided its `status` and its `session` beside
  three columns of blank rows.

A packing is judged on whether every column can say at least `MIN_VALUE_WIDTH`
(8) of its value, not on whether every value fits whole — a column that cannot
say everything elides (decision 5) rather than closing. Refusing to elide let
one long value collapse the panel to a single column and push the fields below
it off the bottom.

### Decision 1: `areas` splits on the toggle, and the whole frame reads it
(M4.7.3)

Milestone 4.6 made `ui::overview::view_of` the single source of the overview's
geometry: the renderer and every mouse gesture hit-test against exactly the
canvas the frame under them was drawn with. The inspector moves that canvas, so
`areas` takes the toggle — `areas(main, inspector_visible)` — and everything
else keeps reading `view_of`. The rect below the canvas is the panel exactly
when `areas` gave it the panel's height, which is what `render` switches on, so
what is drawn there cannot disagree with the room made for it.

The guard that this is right is milestone 4.6's own
`overview_geometry_matches_its_hit_test`, which now runs with the panel in
place. Its second terminal grew by the panel's height (20 rows to 27), which
leaves the canvas under test the same sixteen rows it had before: at twenty rows
the canvas is nine and none of the fixture's boxes fall inside it at that pan,
so the sweep had nothing to check. Nothing else in that test changed.
`the_canvas_loses_exactly_the_inspectors_height` adds the converse: a click on
the panel, on a cell where the layout puts a box just below the canvas, must
select nothing. Reverting the mouse path to the inspector-blind geometry selects
that hidden box and fails that assertion.

### Decision 7: `i` is bound in the overview only (M4.7.3)

`i` toggles from tree-mode navigation, gated on the overview being open — the
one place the panel is drawn. The canvas changes height under the toggle, and
`set_graph_viewport` settles that before the next frame, so the selection is
revealed into the rows the toggle gave back.

### Milestone 4.6's footer is still reachable, and still tested (M4.7.3)

Decision 1 replaces the single line, and decisions 6 and 7 keep it: it is what
`i` returns to and what a short terminal shows. Milestone 4.6's four footer
tests therefore still assert it, opened through a helper that turns the
inspector off, rather than being deleted.

### `ui/mod.rs` was split (M4.7.3)

It stood at 599 lines and the changes above pushed it over, so its test module
moved to `crates/tui/src/ui/tests.rs`. This closes the follow-up that recorded
the file as over-long, but the move was not verbatim: besides the disclosed
`overview_geometry_matches_its_hit_test` terminal-size change, decision 1 also
forced `overview_replaces_the_terminal_with_the_graph`'s expectation to change,
from the single-line footer (`"⠋ 1 api-worker  claude  claude-opus-5
working"`) to the panel's own text (`"│ model    claude-opus-5  sub-agents  3,
2 running"`). At the `200x50` size that test renders, the inspector is visible
by default and replaces the single line the old string asserted on, so the old
string can no longer appear; the new one is the panel's rendering of the same
selected window.

### The smoke stage covers decision 11's fallback arm (M4.7.4)

Stage 9c creates one Claude window whose script spawns two root sub-agents,
filters the overview to one of them, selects it with `l`, and polls the
overview's own pane for `spawned by  <n> insp-1`. Root sub-agents have no
`parent_id`, so this is the arm that resolves to the owning window; the nested
arm is covered by `spawned_by_names_the_parent_subagent` and by the wiring
test that clicks a sub-agent two levels down. The check is scoped to the pane
because the sidebar carries the same label and the same window name on the same
screen — `spawned by` is the panel's own vocabulary, and the pattern asks for it
and the window's name together. Defaulting `inspector_visible` to false fails
this stage and no other.

### The reclaimed row is pinned now (carried from the M4.7.1/.2 review)

When the title already showed a sub-agent's label whole, the renderer drops the
`task` field and hands the row it had reserved back to the column flow. At the
width the existing pair of tests uses, that row changes nothing — reverting the
reclaim left all twelve panel tests green.
`the_dropped_task_field_hands_its_reserved_row_back` puts the same sub-agent on
a 24-column panel, where its seven flow fields outnumber the five rows one
column has: the fifth row carries `kind` only because the dropped field gave it
back. With the reclaim reverted this test, and only this test, fails.

### Still open

Carried from M4.7.1/.2 and untouched here:

1. **`spawned_by` calls `app.rows()`**, a second tree build per frame while a
   sub-agent is selected. `inspect(row, app)`'s signature is this brief's, and
   the renderer has the rows in hand; changing it is a follow-up, not a
   deviation.
2. **`shorten_home` reads `$HOME`**, so `inspect` is not a pure function of
   `App` alone — exactly what the footer it replaced already did.
3. **The `task` field still elides on its last line** when the rows left cannot
   hold it. The panel's height is fixed at 8 by decision 2.
